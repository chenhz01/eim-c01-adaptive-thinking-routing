# P03 · 05-thought-layer

> 属于 [P03 confidence-gated-reasoning-switcher](../README.md) 的文档分册。


## 第一性原理：它依赖哪条不可再分的假设

把本仓剥到不能再剥，只剩两条。**第一：不同的请求需要不同强度的计算，而强度可以被标价。第二：在动手之前，有一个便宜的信号能告诉你这次需要多少。**全篇其余内容都是这两句话的推论，以及它们各自失效时会发生什么。请注意这两条里，只有第一条与本仓代码有关，第二条完全不在代码里——但它承担了整套机制几乎全部的价值。

### 第一条假设：计算强度可被标价

这条在今天几乎是常识：同一个问题可以用不同预算解，贵不一定对，但对的概率更高。它之所以能成立，是因为**质量对投入的响应是有形状的**——本仓用 `exp(-decay·d)` 表示，三条曲线的 decay 分别是 3.0 / 1.2 / 0.4，也就是说慢档在同样难度下衰减得慢得多。如果这条不成立（三档质量相同），整套机制立刻失去意义。值得强调一个常被忽略的推论：**这条假设要求三档之间存在「可测量的差异」，而测量本身就是成本。**实验 3 的 140 点网格扫描需要约 56 万次决策评估，远超路由自身的全部运行开销。机制的价值源于法规，而法规的获取远比机制本身昂贵——这个不对称在所有「智能路由」类系统里都存在，本仓只是把它算给你看了。

### 第二条 taken （不在代码里的那条）：存在可用信号

这条是整个机制的真正地基，而它完全不可见于源码。`pick()` 的函数签名里写着 `confidence`，但没有任何一行代码在检查这个数字是否真的包含信息。实验 11 把这个地基单独抽出来称量：把输入换成均匀分布随机数（信息量为零），机制照样输出 Q=0.6318 / C=12.19 这样看起来体面的结果。反过来算：完美信号下总成本 18.30，其中 12.19 与信号无关 —— **33.4% 的支出由信号驱动，66.6% 由结构自身的默认形态驱动。**这个比例是本仓给出的最有实用价值的数字之一，因为它直接告诉你该在哪里投入精力：如果你花了三个月优化路由逻辑，你最多能动的是那三分之一；而如果花同样的时间去改善 confidence 的质量，你动的是那个乘数。

### 推导链：从两条假设到六行代码

① 存在可标价的计算强度 → 存在若干个可选档位 T；② 存在一个与难度单调相关的信号 c → 存在一个从 c 到 T 的映射 f；③ f 若要零依赖、零状态、可枚举 → 最简单形式是数轴上的若干切点；④ 三档需要两个切点 → `hi` 和 `lo`；⑤ 边界归属需要与直觉一致（高置信归快档）→ 用 `>=` 和 `<=`；⑥ 余下的输入需要一个出口 → 兜底返回中档。每一步都是上一句的必然，没有哪一步是「聪明的」。这套推导的诚实之处在于：**它证明了本机制没有任何巧妙之处**，它只是在最弱的假设下能成立的最小结构。而它的诚实代价是——第 ⑥ 步那个「余下的出口」，正是实验 9 里 NaN 溜进来的那扇门。最小结构的兜底，永远是它的阿喀琉斯之踵。

### 反过来的问题：如果假设二不成立，第一条还有价值吗？

有，但需要换一个形态。实验 11 的第 ⑤ 组（常数 0.6，等价于「永远中档」）给出 Q=0.5866 / C=5.00。在完全没有信号的前提下，**最优策略不是路由，而是选定一个折衷档位然后永不改变。**这是一个重要的结论：路由不是「有限预算下的必然产物」，它是「有限预算 + 有信息信号」这两个条件的联合产物。只满足前一个条件时，正确答案是极简而不是精巧。而行业里大量的路由系统恰恰是在信号未经检验的情况下被建起来的——它们承担了三份维护面，换来的是介于随机和不用之间的性能。

> 所以本机制的第一性原理不是「难的用贵的」，那只是一句口号；它是：**「在计算可被标价、且存在一个经得起检验的难度信号时，把决策压缩成数轴上的两个切点是成本最低的实现。」**这句话里有三个条件从句，每一个漏掉，后面的结论就不成立。本 README 的其余部分就是在逐个拆卸这三个从句。



## 反事实推演：六个「如果反过来」

反事实推演的目的不是抬杠，而是找出「哪些部分是随便选的，哪些部分是被迫的」。能被改动的随便选的部分叫作参数，改了就崩的叫作结构；混淆这两者是绝大多数过度设计的来源。

### 反向做：难的用便宜档

这就是实验 11 的第 ④ 组——把 `c = d`（越难越自信）送进去。结果 Q=0.5845 / C=12.47，与「完全不用信号、永远中档」的 0.5866 / 5.00 相比，**质量几乎相同（-0.0021），成本贵了 149%。**这条比单纯变差更有教育意义：它不是「机制失效」，它是「机制照常运转、报表照常好看、但整套装置没有任何正面贡献」。一个坏信号最大的危害不是拉低性能，而是**它会让整套系统继续被维护下去**。识别它的方法只有一个：把信号替换成随机数，跑一遍，看两者差多少。如果差值在一个数量级以内，你的路由基本可以判定为装饰品。

### 不做：永远用最贵档

这是所有对照的基准：Q=0.8261 / C=25.00。注意它是**质量上界**——本机制的默认配置（0.7880）差它 0.038，而 ORACLE（拥有完美难度信息并按最省方式选档）也只有 0.8222，低于 0.8261。这个反常现象值得停下来想一分钟：**连全知都比不上「全用贵档」？**答案是 ORACLE 的目标函数是「达到 target 的最便宜档」，而我们的 target 设定让它在部分样本上选了便宜档。这揭示了一个常常被掩盖的真相：**任何「按目标质量选档」的机制，本质上都已经接受了「这一次可以不够好」这个前提。**如果你不能接受这个前提，那你真正需要的是全贵档 + 事后压缩（P04），而不是路由。

### 做过头：十档而不是三档

直觉上档位越多越精细。但请把实验 3 的结论放到这里：140 个**两参数**组合里，能达到 Q≥0.80 的已经有 30 个可行且成本最大只差 1.13 倍。换句话说，即使是在参数空间被极度放大之后，可调出来的结果也挤在一条窄带上。档位从 3 增到 10，增加的是 7 份维护面、7 份回归集、7 倍的顺序敏感性，换来的是在这一条窄带上多出几个取样点。**更致命的是：档位越多，边界值就越容易撞上。**三档时 `pick(0.8)` 归快档只是一个小偏差；十档时每一次成都市的边界判定都会影响一部分流量，而每一次新增档位都会多出一个边界判定，每个判定在 IEEE 754 下都有 NaN 的那扇后门。复杂度增长与失败面增长不是同阶的——后者更快。

### 只做一半：只有一个阈值

两档版本的读数 Q=0.8191 / C=23.10，**质量反而高于三档的 0.7880**。这一组是很好的「减少复杂度反而更好」的证据。但它不能简单读作「两档优于三档」，因为两者的成本差了 4.79 —— 在固定质量口径下（实验 4b）三档始终能以更低成本达成同一目标。正确的读法是：**两档和三档是同一条前沿上的两个不同位置**，它们不是优劣关系，而是「你愿意接受多少质量」的选择。把一个 Pareto 前沿上的取舍说成「哪个更好」，是技术讨论里最常见的偷换。本仓在「替代方案」一节的六维对比表里刻意并列了两者，就是为了让这个取舍无法被藏起来。

> 四组反事实合起来给出一个不太舒服但很有用的判断：**这套机制的四个自由度里，三个是假的。**档位数量、阈值个数、是否路由——这些都只是在前沿上选位置；唯一真正的自由度是 confidence 的质量。省下那么多力气去调阈值，不如去改善那个输入。



## 跨域同构：它在自然与工程中的同形物

跨域同构不是为了把话说得漂亮，而是因为**别的领域已经为同样的坑付过学费了**。下面四组里，前三组是真的同构，第四组「哪里不同构」往往比前三组信息量更大——因为识别出「这次不一样」，才是类比有没有价值的真正检验。

### 生物：免疫系统的两级响应与 triage

先天免疫便宜、快速、粗糙，几分钟到位；适应性免疫昂贵、慢、精准，需要数天。身体不会因为「这只是个小伤口」而跳过先天免疫，也不会因为「风险未知」而跳过适应性免疫。它与本机制的结构同构：**用便宜的一层过滤绝大多数，把贵的留给少数。**但这里有一个本机制学不会的细节：先天免疫**从不宣称**自己在做最终判断，它只负责「撑到适应性免疫上来」，两层是串联而非二选一。对照看，我们的三档是互斥的——选了快档就没有第二道防线。这组类比因此给出了一个改进方向：**快档之后接一个廉价的复核（verifier），而不是把快档当作终点。**这正是家族里 `multi-agent verification` 那一簇在做的事。

### 经济：信贷风控的三层审批

小额自动批、中等金额走规则引擎、大额走人工审批——完全相同的一个形状，而且银行业花了四十年把这套东西调成熟了。它给本机制的最大启示是：**银行从不让一个信号单独决定三层的归属。**信贷审批会用金额、征信、历史行为、反欺诈等多个信号组合，因为它们吃过「单一自评信号在系统乐观时集体失控」的亏。把它翻译过来：本机制用单个 `confidence` 做判定，等于整个风控只问了借款人一句「你觉得你能还钱吗」。实验 5 里 gamma 从 1.0 掉到 0.25 造成的质量塌方（-32.6%），在银行业有一个专有名词来形容这种事：系统性顺周期。一个所有人都同时变乐观的系统，会在最需要谨慎的那一刻放松标准。

### 军事与医学：分诊（triage）

战场上按伤情把伤员分成四色标签，急诊室按危急程度分级。它与本机制共用同一个数学骨架：把异质输入映射到有限资源等级。分诊制度里有一条本机制必须学的铁律：**任何分类决策都必须可以被复核，并且必须记录分类者是谁。**因为在实际搬运链里，误判的代价不是账单而是人命，所以制度不允许「系统说是中等级」。还有一个更微妙的同构：成熟的分诊体系都有**升级通道**——低等级伤员在等待中可以随时被提升到高等级。我们的三档是单向的：一旦判定为快档就没有回头路。这条「不可逆性」是飞行员 kept ntawm 的真正来源，而金融风控领域的改进往往是「能不能回头」，而不是「第一次判得准不准」。

### 哪里不同构：这次真的不一样的地方

最重要的一处不同构：**在物理世界里，资源池的大小是固定的。**战场上的外科医生数量不会因为你多标记了几个红标签而翻倍。而 LLM 的成本结构里，容量是可以购买的、价格是在持续下跌的、便宜档的质量每年都在向贵档靠近。这导致一个根本不同的动态：**随着时间推移，这套机制的收益会自动衰减**——不是因为它变差了，而是因为「档位之间的质量差」在收敛。当便宜档追上贵档的那一天，路由的最优答案就是「永远用便宜档」。这意味着本机制不是一个可以装上就不管的设备，它是一个**需要定期重新审视是否还有价值**的东西。第二个不同构同样重要：物理分诊的错误是可见的（伤员死了会被发现），而路由逃逸的错误常常不可见（答案看起来没毛病）。不可见的错误不会被汇报、不会被复盘、不会进 lessons learned——它是一个**不会自己长出修正力**的系统。这一条是本机制最需要外部制度来补的部分。

> 四组类比给出同一个建议：**把本机制看作一个需要被外部制度包围的技术点，而不是一个可以独立交付的功能。**分诊需要复核與升级通道，信贷需要多信号与逆周期资本，免疫需要串联而非互斥——它们指向的都不是「把 classifier 调准」，而是「给它周围加上什么样的约束」。



## 失败考古：同类尝试的墓志铭

本节记录三种同类尝试的死法。它们的主人都很聪明，方案都通过了自己的内部评测，而且都发表在看得见的地方——这正是值得写下来的理由：**失败的普遍形态不是被驳倒，而是被遗忘。**

### 墓志铭一：缓存分层的折扣率坍塌（CDN 时代，2000s）

把请求按热度分到内存缓存、SSD 缓存、回源三层，与本仓三档在结构上是同一个东西。它死在一个地方：命中率的微小下降被**回源成本的非线性放大**。 内存层错一次，代价是几十毫秒；回源层被挤一次，代价是整站雪崩。这与本机制的「逃逸 vs 浪费」不对称是同一件事：逃逸一次损失的是用户信任，而信任的恢复成本远大于当初省下的 token。给本机制的教训：**永远不要按对称的成本来建模这两类错误。**在本仓的合成数据里，逃逸被定义为质量差 >0.30 的事件，而实验 5 里 gamma=0.25 时它的发生率是 15.7%——如果那时候有人只看平均质量下降了 32.6% 而不去数逃逸事件，他会把它归类为「模型整体变差」而不是「路由在伤人」。分类错了，修复方向就错了。

### 墓志铭二： speculative decoding 的接受率幻觉（2023–2024）

用小模型起草、大模型批，理论上能显著提速。大量实现上线后发现收益远低于论文，原因是：**接受率对分布极其敏感，**起草模型与验证模型的「契合度」在论文数据上很高，在真实流量上快速衰减。它与本机制共享同一个病灶——**方案的价值不在自身，而在两个组件之间的契合度**，而这个契合度会漂移。本仓实验 5（校准漂移）就是把这个病灶用一个参数（gamma）显式表示出来：gamma 从 1.0 到 0.8，质量掉 0.018；到 0.25，掉 0.2571。讽刺的是：**speculative decoding 至少会告诉你接受率是多少**，它自带仪表盘。而本机制的 `confidence` 通常是黑盒的自评，连这个仪表盘都没有。因此本 README 在生产化清单里把「记录 (confidence, 事后正确性) 三元组」列为 P1 而非 P3——没有这张表，你连自己在漂移都不知道。

### 墓志铭三：MoE router 的负载坍缩（2021– ）

混合专家模型的路由会把 token 发给 top-k 专家。它反复出现的问题不是选错专家，而是**所有 token 都想挤进同一个专家**——路由坍缩（routing collapse），以及随之而来的负载失衡。这与本仓的哪一点对应？实验 7 的 hard 分布：**98% 流量落 slow，门控相对全 slow 只省 1.7%。**这是一个已经发生的坍缩，只是它在 LLM 路由场景里不容易被认出来，因为「全走最贵档」看起来是保守且安全的。 MoE 社区给出的解药是加负载均衡损失（auxiliary loss）——一个**显式惩罚集中**的项。平移过来就是：如果你的监控只盯着「平均成本」和「平均质量」，你会错过坍缩；你必须额外盯着**档位占比的分布熵**。占比趋近 0/0/100 就是坍缩的信号，此时正确的动作不是调阈值（实验 4c 已经证明调了也没用），而是承认这个任务池不适用。

### 共同死因与幸存者偏差

三块碑指向同一个死因：**它们都把一个会漂移的契合度当成了系统的常数。**内容热度会漂移、起草与验证的契合度会漂移、专家偏好会漂移、而 confidence 与真实胜率的关系当然也会漂移。这个规律的实用形式是：**凡是不在你的定期监控列表里的量，都应该被默认为正在漂移。**至于幸存者偏差：你现在能看到的路由类方案，绝大多数是成功的那些——而成功往往来自「任务池恰好合适」这个不可迁移的条件。实验 7 里从 easy 到 hard，机制收益从有意义的 26.8% 崩到 0.04%，而这两组用的是**同一份代码、同一套阈值**。代码从来没有变过，变的是环境。一个方案的成败有相当一部分由环境而非方案决定，这一点在「某某公司用它省了 X%」这类分享里永远不会出现在第一页。

> 考古学的用处不是让人怀旧，是让人**在动手之前就能认出正在重演的那个坑**。本机制面临的三块碑，对应的三个监控项分别是：逃逸事件的绝对计数（不只是平均值）、confidence 与真实结果的当日联合分布（推定 gamma）、档位占比的分布熵。这三项在《生产化改造清单》里分别列为 P1 与 P2，不是偶然。



## 自我反驳：站在反方最强处攻击自己

本节站在反方最强的地方攻击自己。反方最强的一击不是「你的参数没调好」，而是更根本的一条，而且它是对的。

### steel-man：你的数据全是假的，所以你的结论一个都不能用

这是最强的攻击，我先把它的最强版本说出来：「本 README 里的每一个数字——0.7880、18.30、66.6%、0.04%、-32.6%——全部出自一个你自己写的合成模型 `quality = exp(-decay·d)`。你设定了 decay 是 3.0 / 1.2 / 0.4，你设定了成本是 1 / 5 / 25，你设定了难度服从均匀分布。在这样的自由度下，你可以合成出任何你想得到的结论。**这不是实验，这是用 extra steps 包装的个人偏见。**」这个攻击无法用「但是我们的模型合理」来反驳——合理性不是论证。任何一个人都可以对 decay 的取值提出异议，而一旦 decay 变了，所有表格里的数字都会变。而且他还可能补最后一刀：「你甚至没有一次真实 LLM 调用，你凭什么叫它 benchmark。」

### 承认成立的部分（很大，必须认）

这一击成立，而且成立的部分比多数作者愿意承认的大得多。本 README 中**没有任何一个数字可以直接用作性能承诺**，FAQ Q3 已经把这句话写在最显眼的位置，这里再强化一次：**你不能拿着「省 26.8%」去说服任何人，因为那个数字是在一个我构造的世界里成立的。**更进一步，连「结构是：信号权重 33.4% / 结构权重 66.6%」这个结论也带构造性——它依赖于三档成本比 1:5:25 这个设定。若把慢档成本改成 50，这个比例会明显变化。我也不得不承认一个更微妙的问题：**合成模型的函数形式本身就隐含了结论。**`exp(-decay·d)` 是光滑、单调、单峰的，它排除了真实系统里常见的「某类任务便宜档反而更好」这样的非单调现象。如果一个效应在我的世界里数学上不可能出现，那我当然观测不到它——这不是没有观测到，这是**事先把它赶出去了**。这一点必须写下来。

### 剩余防线：合成实验能回答什么，不能回答什么

防线只有一条，但它是一条实线：**合成实验的价值不在于预测数值，在于测量关系的形状。**具体来说，它确有能力回答以下三类问题——① **单调性与翻转**：实验 9 的 9 次 33 就给出 0.8 走向，实验 3 给出「可组合之间存在 1.13 倍以内的差异」这样的**关系断言**，实验 4c 给出「偏难分布下收益趋近于零」的形态。这类结论对具体参数值不敏感，而对**结构**（三档、两个切点、一个信号）敏感，因此它们是本 README 里唯一值得被带走的东西。② **失效模式的存在性**：NaN 走中档（实验 9）不依赖任何参数——它是 IEEE 754 的语义后果，在真实系统上同样成立。③ **必要条件的清单**：零信息基线的存在（实验 11 第 ③ 组）是一个**结构必然**，任何三档门控都要通过这一关才能自称有效。而它**不能**回答：任何具体百分比，以及任何关于哪个模型更划算的说法。把这两件事分开，这篇文档就从「一份广告」变成「一份规格」。最后补一句自辩：**一份藏着自己局限的文档也有偏见，但那是可纠正的偏见；一份不写局限的文档，偏见不可纠正。**

> 所以正确的读法不是相信这些数字，而是**把这套实验当作一组探针**：它们插在你自己的系统上，测出来的数会和这里完全不同，但探针的形状——零信息基线、固定质量口径、分布敏感性、NaN 通道——可以原样复用。**这是一份方法论，不是一份成绩单。**



## 认识论：凭什么相信它有效

「凭什么相信它有效」这个问题，必须先回答「凭什么相信任何东西有效」。本仓采用家族旗舰仓统一的三层证据标准：存在性、可迁移性、外部证实。

### 证据类型清点（诚实分级，不许混装）

**A 类 · 结构性事实（不依赖合成参数）**：① NaN 落入中档（实验 9）；② `pick(0.8)` 归快档、`pick(0.4)` 归慢档的边界语义（实验 9）；③ 越界值 1.5 与 -0.2 的行为依赖 IEEE 754 比较语义而非设计意图；④ 零信息基线必然存在且必然非零（实验 11 第 ③ 组）。这四条在真实系统上复现不需要任何运气。**B 类 · 形状性结论（对参数值不敏感，对结构敏感）**：① hi/lo 更像质量旋钮而非省钱旋钮（实验 3：1.13 倍 vs 质量极差 0.2816）；② 偏难分布下收益趋近于零（实验 7 / 4c）；③ 校准漂移的破坏力显著大于估计噪声（实验 5 vs 实验 6）；④ 「永远中档」在某些成本结构下优于整套门控（实验 4）。**C 类 · 数值性结论（严格绑定合成世界，不可外推）**：所有百分比与绝对值。本 README 中的绝大部分表格属于 C 类。**一个读者如果不做这个分级，他会错误地把 A 类当 C 类用（过度谨慎）或把 C 类当 A 类用（过度自信）。**

### 失效条件：本 README 在什么情况下整体作废

列出可验证的失效条件，是让一份文档可被信任的最有效方式——因为它给了读者一个**不需要信任我也能证伪我**的把手。失效条件一：若你的 `confidence` 从未被单独标定过，那么本文关于「-months 校准漂移」的全部内容都只是提醒，而你的实际处境可能已经处在 gamma=0.25 那一端。失效条件二：若你的三档来自同一个模型的不同 sampling 参数，那么 `quality(d)` 的三条曲线不会像本仓合成模型那样分离 7.5 倍，「route 有效」的前提直接垮掉。失效条件三：若你的任务池在一个月内难度漂移超过一个 Beta 参数，实验 7 的 easy/hard 对比就是你的未来。失效条件四：**若某天便宜档的质量追上了贵档**——这在 § 模型能力曲线上是完全可以预期的事。这四个条件都不是危言耸听，它们每一条都对应一个已经列举出的实验。

### 可反驳形式：我承诺接受什么样的反例

一个不可以被反驳的主张不是知识，是广告。因此本仓明确列出自己会低头的形式：① 你在真实系统上做了零信息基线测试（把 confidence 换成随机数），发现门控与之差异 >2 倍——则本文「结构占三分之二」的判断在你那里不成立，我接受；② 你在偏难分布上做出 >10% 的固定质量口径节省——则实验 4c 的结论被推翻，我接受，并请求你把数据与脚本发出来，我会更新本文；③ 你证明了 `confidence` 与真实胜率在你的系统上稳定单调且跨越半年不漂移——那么本文最悲观的那一章（校准漂移）对你不适用，恭喜。**我不接受的反驳形式**：指出某句形容词用了夸张修辞、指出某个百分比小数点后两位算错、或指出「别人家的方案更好」。这三种都不构成对核心命题的攻击。把它写在这里的目的很直接：**一份愿意明确列出「我会怎样低头」的文档，比一份到处防守的文档更值得读。**

> 认识论这一章最后想说的是一句不太中听的话：**关于这套机制，你真正需要测量的是你自己的系统，而不是我这套合成模型。**本 README 能给你的全部东西，是一组探针的形状和一份失效条件的清单；剩下的工作在你那边，而且它不可能由读文档来代替。



## 规模律：10× 与 100× 时先坏在哪

规模律问的是：把流量乘以 10 和乘以 100，最先坏的地方在哪？有趣的答案是——**最先坏的往往不是性能，而是统计的可观测性**，而这一点在小规模测试里根本看不出来。

### 10× 规模：先坏在「读不出数」而不是「撑不住」

剧透 optou this tulugfestoe — 路由本身是 O(1)，一秒跑十万次也不成问题。率先出问题的是**监控的分辨率**。实验 10 给出了明确的尺度：在 gamma=0.7、sigma=0.15 的现实漂移条件下，逃逸率的 95% 置信区间在 n=50 时是 ±214%，n=200 时 ±97%，n=1000 时 ±39%，直到 n=4000 才收到 ±21%。10× 规模意味着每天百万请求，看似样本充裕——但问题在于**你要监控的不是全量平均值，而是分桶后的值**。按任务类型分成 50 个桶之后，每桶每天两千条，此时每桶的逃逸率置信区间回到 ±40% 量级。**10× 的真正挑战是分桶之后的分辨率，不是总量。**这也解释了为什么大厂里常见「某个细分赛道质量崩了半年没人发现」——因为那个桶的样本量从来不够。

### 100× 规模：先坏在「条款间的结构」而不是档位

到百万 QPS、多租户、多业务线时，三档会自然长成「每个业务线一套三档」，也就是 30 到 300 个档位。这时实验 3 的结论会以一种新方式报复你：**可组合参数爆炸，而每一个 ~ optimal 组合都挤在同一条窄带上。**这意味着巨大的配置面之下几乎没有真实的调节空间，但每一个配置项都需要有人负责、需要文档、需要值班同学能看懂。第二个一百倍问题更根本：多租户下，**不同租户的最优点是互相冲突的**。实验 7 已经演示了同一个现象：easy 池的最优阈值搬到 hard 池上基本没有意义。在多租户环境里，这个冲突会从「两个池」变成「两百个池」，而折衷的做法通常是一个谁都不最优的中间值。第三个一百倍问题是之前没出现过的：**当流量足够大时，路由本身成为单点依赖**，它的任何静默行为（NaN 走中档）会被放大成每天数万次无人知道的降级。规模把「小概率坏事」变成了「每天必然发生」。

### 前兆指标：能提前多久看到崩塌

根据现有的实验，给出三个可观测的前兆，按敏感度排序：**① 档位占比的分布熵（最敏）**——它比任何质量指标都更早反映分布迁移。坍缩到 0/0/100 时，机制已经在结构上失效，而平均质量可能还看不出问题。**② confidence 分布的形状（次敏）**——不是它的均值，是它的整体形状。校准漂移会先把分布整体推向高端，之后才反映到质量上。实验 5 里 gamma 从 1.0 到 0.8 时质量只掉 0.018，但 fast 占比的上升已经开始。**看占比可以比看质量早一个观测窗口发现问题。****③ 固定质量口径下的成本（最钝但最准）**——就是实验 4b 的做法。它综合了前两者，缺点是算它需要一次完整重跑。建议节奏：①② 每日，③ 每周。**这个节奏是根据「哪个指标先动」排的，不是根据「哪个指标算起来方便」排的。**

> 规模律给出的结论与直觉相反：**这套机制的弱点从来不是吞吐量，而是可观测性。**它足够快、足够小、足够便宜，因此它的失效会以「统计上不可见」的方式发生。这就是为什么本 README 反复强调「记录三元组」与「分桶监控」——这两件事在小规模看起来是多此一举，在规模上来之后是唯一的救命绳。



## 激励相容：谁有动机用它，谁有动机绕过它

任何机制被装进组织之后，都会立刻长出一圈围绕它的利益。本节问三个问题：谁因为它而变得更好、谁有动机绕过它、以及制度应该怎么设计才能让真实信号浮上来。

### 受益者：成本团队获得了一个新的可汇报对象

最直接的受益者是承担账单的一方。路由给他们一个可以被写进汇报里的数字：「本季度通过智能路由节省 26.8%」。这与地位的错配在于：**省下来的钱马上可见，丢掉的质量几乎永不可见。**本仓的合成数据里这两个量的分布严重不对称——成本是每次调用都发生的、连续的、可被 SUM 的；而逃逸是一个低频的、离散的、常常没有被标记的事件。这种不对称会造成系统性偏差：哪怕两个团队的权重在制度上完全对等，实际决策也会被能报出数字的一方主导。识别这个偏差的方法很朴素：**问成本团队一个问题——「如果今年这套路由被拆掉，有几个人会主动要求把它装回来？」**如果答案是「取决于汇报口径」，那它的收益主要在叙事层。

### 绕过者：产品与质量团队的三条隐蔽路径

承担用户体验的一方天然想绕过它，而且他们的做法往往不会被记录为「绕过」。**路径一：把 hi 悄悄调高。**提高进入快档的门槛等价于让更多请求走贵档，在他们的心智里这不是绕过，是「质量加固」。而实验 3 已经说明 hi 移动的实际效果主要是质量轴上的位移——所以他们的直觉在这件事上是对的，只是没法用数据自证。**路径二：在自己的服务里绕过路由直接调慢档。**这是最干净也最恶劣的一种，因为它让中心化的账单失真：成本团队看到的 mix 不再是真实的 mix。**路径三：把慢档包装成「默认」然后不再提交路由参数。**效果是路径一与二的叠加，且因为它看起来像「没用这个功能」而更难追责。这三条路径的共同点是：**它们都不可见于 metrics**，因为它们改变的是「谁在调用」，而不是「调用是否正常」。

### 制度设计：让真话比假话便宜

三条可行的设计，都建立在「改变谁承担什么」而不是「说服谁」之上。**① 事后清算，而不是事前配额。**把估算的节省按季度返还记账，但把逃逸造成的返工与投诉**在同一张报表上并列显示**。让两个数字在同一个格子里出现，是改变行为最便宜的方式。**② 让价格信号进入调用方。**如果慢档对调用方内部计费更贵，绕过行为就从「安全选择」变成「花钱的选择」。实验 11 第 ④ 组给出的是同一个道理的负面版本：当信号指向错误的方向时，人们会做出糟糕但自洽的选择——**所以首先要保证价格信号的方向是对的，否则激励放大会放大错误。****③ 冻结期与拥有者。**把 hi/lo 标为受控配置，任何改动需要标明日期、样本量、改动者与理由（《生产化改造清单》P3 项）。这不会阻止绕过，但它把绕过从匿名变成具名。最后一条经验性的判断：**在这类系统里，「谁有权改阈值」的权力归属，比「阈值取多少」重要得多。**前者是制度，后者是参数；参数会被调整，制度不会。

> 激励这一章的结论可以压缩成一句：**不要指望任何一方出于善意给出真实评估。**要指望的是设计出一种局面，让给出真实评估是各方最省力的那个选项。把成本和质量放进同一张表、把价格信号接到调用方、把阈值改动变成具名行为——这三件事都比任何一次「大家要客观」的会议有效。



## 权力与伦理：它让谁更强、让谁更弱

一个「让某些请求得到更少计算」的机制，天然涉及分配正义。本节不写道德表态，只写三类可被追踪的事实：谁变强、谁变弱、以及哪里必须有红线。

### 受益方：能把任务说清楚的人

路由系统有一个几乎无人指出的偏好：**它偏爱「容易被判断难度」的任务。**一个格式标准、领域常见、置信度容易估准的请求，会被准确路由；而一个新颖、跨界、语言混杂的请求，它的 confidence 往往是失准的。在真实系统里，后者会更多地被误判——而误判的方向取决于当时的校准状态。在公司内部，这意味着**成熟业务线会从路由系统吃到更多红利**，而探索性业务线会更频繁地承受它的失败。这个问题的棘手之处在于：统计上完全看不到它。总体的 Q 和 C 都在正常范围内，只有按业务线分桶才能看见——而这正是实验 10 警告过的那个分辨率陷阱。可行的缓解：把「置信度估计误差」按业务线分桶监控，而不是只监控总体。

### 受损方：无法申诉的那一部分用户

更值得警惕的是对外场景。**当一个用户的请求被判给便宜档，他不会知道这件事，也不会有一个申诉入口。**他只会得到一个稍微差一点的答案，然后据此做出一个稍微差一点的决策。这类伤害有三个特征让它难以被治理：隐蔽（用户不知道发生了路由）、分散（单次损失很小）、归因困难（无法证明「如果用了贵档会更好」）。在 § 指引上有一个清晰的类比物体：**航空业的分级理赔不适用，但金融业的产品适当性管理是适用的先例**——后者明确要求「高风险产品不得向无法承受风险的用户推荐」，这是一个把「降配」限制在特定场景之外的成熟制度。把这条平移过来得到本机制的红线：**在高风险、难验证、后果不可逆的领域，降配这件事本身就不该发生，****而不是应该受到更严格的准入。**

### 红线与可执行的设计

把它落到可以写进代码的形式，一共四条：**① 不可压缩清单。**识别医疗、法律、金融、安全等类别，从路由里完全剔除，写死走昂贵档。技术上只是几行配置。**② 结果必须可解释。**用户问「为什么这次回答这么短」时，答案必须是设计出来的（比如明确的分桶规则），而不是路由表算出来的。这一条与上面的「不可压缩清单」一起构成了可问责性的最低要求。**③ 提供显式申诉/重算入口。**一个「请用更强的模型重算一次」的按钮，是把隐蔽伤害变成可见选择的成本最低的方式。它还有一个副产品：申诉数据是标定 confidence 质量最好的标签来源。**④ 保留一条不参与优化的保底通道。**当有人试图把所有流量都推进优化器的那一刻，团队至少有一句已经被记录下来的话可以引用。写下这几条的意义不在道德姿态，而在于：**当有人问「这一步凭什么走了便宜档」时，答案必须是设计出来的，而不是账目算出来的。**

> 伦理这一章想留下的不是态度而是程序。「省下的这笔钱向用户收了吗」这个问题一旦被问出口，它就应该有一个写在配置里的答案，而不是一个写在会议纪要里的答案。



## 十年尺度：它会被什么取代

十年尺度上问三件事：什么技术变量会改变它、它会被什么取代、以及——最重要的——什么不会变。

### 技术变量：模型正在把预算决策内化

最明确的趋势是：**模型自身开始决定想多久。**这个变量对本机制的影响是釜底抽薪级别的：当思考时长的决定权从「外部的一句话选档」移到「模型内部的生成过程」时，本机制的整个前提——存在一个外部的、可观测的、能被我们切分的决策点——就不复存在了。我的判断（这是判断，不是预测，没有外部数据源）是这条路会在 2 到 5 年内走到主流。判断它是否已经到来的可观测信号很朴素：**如果你开始无法向用户解释「为什么这一次想了这么久」，说明预算的决定权已经移到了模型内部。**到那时，本机制会从「一个产品组件」退化为「一个用于理解这段历史的文献」。还有第二个较慢的变量：便宜档与贵档之间的质量差在收敛。这会先让机制的收益变小（还记得「跨域同构」一章里说的「收益会自动衰减」吗），再让它变得不必要。

### 取代路径：三种形态，都不是本机制的改良版

**形态一：内化。**如上所述，模型自己决定深度，外部路由消失。**形态二：变成定价的一部分。**当供应商自己提供「auto」档位并按实际用量计费时，路由这门手艺会被供应商吃掉——就像 CDN 吃掉了一部分缓存分层的工作一样。届时留给使用者的决策只剩「用不用 auto」，而不再是 hi/lo 取多少。**形态三：变成治理而不是优化。**这可能是本机制最体面的归宿：当优化的价值随着 § 模型的内化而消失后，剩下仍有价值的是「红线清单」「不可压缩清单」「可解释与申诉」那部分——也就是伦理那一章的全部内容。换句话说：**本 README 里最可能被时间留下来的，是十章中看起来最不技术的那一章。**这并不是一个安慰性的说法，而是一个关于技术寿命的观察：优化器会被更好的优化器取代，约束不会。

### 不变的部分：三条可以带走的判据

第一条：**没有一个上了双肩的机制会自我修正。**所有静默失效的共同点是隐蔽而非剧烈。这条不随技术形态变化。第二条：**输入信号的质量决定机制的上限，而且这个上限无法由机制内部的精巧来突破。**实验 11 的 33.4% / 66.6% 这个比例会变，但这条关系是结构性的。无论是梯度奖励路由、MoE router 还是人肉分诊，这条都成立。第三条：**凡是有读者的分配决策，都需要有能被质询的依据。**这条甚至不是关于 LLM 的，它是关于任何「把有限资源分给不同对象」的制度。把这三条写成判据而不是结论，是有意为之：**一个用技术名词写成的结论会在技术换代的那天死去，一个用取舍关系写成的判据不会。**即使本仓的代码明天被删掉，这三条仍然成立——这大概是一份技术文档能够要求的最高评价。

> 十年之后回头看，`pick(confidence, 0.8, 0.4)` 这六行大概会显得过时甚至幼稚。但「先看资源是否稀缺，再看信号本身的质量，最后才看形式」这个次序不会过时。本 README 用两万字想说的其实就是这一句。
