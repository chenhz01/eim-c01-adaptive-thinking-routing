# P03 · 01-problem-and-model

> 属于 [P03 confidence-gated-reasoning-switcher](../README.md) 的文档分册。


## 问题：它到底在解决什么

### 真实场景

同一个问答服务，一天里进来的请求差异极大。「1+1 等于几」和「把这份合同第 7 条的抗辩理由推演三层」的成本不该一样，但如果你对所有请求一律用最强模型，账会难看到财务先提意见。最朴素的省法是「难的用强的，简单的用弱的」——这句话每个工程师都说过，问题是**谁来判断难不难**。你手头通常只有模型自己给的一个数：`confidence`。于是本仓做的事就是把那句话落成六行：`confidence >= 0.8` 走快档，`<= 0.4` 走慢档，中间走中档。它零依赖、三步可接、在任何语言里都能三分钟重写一遍。真正难的问题不在代码，而在那个 `confidence` 到底值几个钱。

### 朴素做法为何失败

朴素做法的失败方式比「失败」更温和——它看起来一直在工作。在受控的合成难度模型里（质量函数 `quality = exp(-decay·d)`，三档 decay 分别为 3.0 / 1.2 / 0.4，成本 1 / 5 / 25），默认参数 (0.8, 0.4) 下难度均匀分布的流量分配是**快档 8%、中档 24%、慢档 68%**。也就是说：**三分之二的流量还是走了最贵档。**整套机制相比「永远用慢档」（质量 0.8261 / 成本 25.00）得到的是质量 0.7880 / 成本 18.30 —— 省下 26.8% 的钱，换来 0.038 的质量下滑。这不算失败，但它远不是宣传语里那种「省一半」。真正的失败发生在另外两种情形里，而且都是从同一个洞漏出去的。**其一：当任务整体变难时，整套机制悄悄退化成「永远用慢档」**——在偏难分布下（Beta(4,1.5)），98% 的流量落入慢档，成本 24.57，而「永远慢档」的成本是 25.00，差别 1.7%。在固定质量目标的公平口径下（实验 4c，目标 Q≥0.75）差距更刺眼：门控最优 24.99 vs 单档 25.00，**节省 0.04%**。你为一个六行函数加上了三套档位、三份 prompt、三份回归测试，换来 0.04%。**其二：机制的收益几乎全部来自输入信号，而不是来自路由逻辑本身。**把 `confidence` 换成随机数 `U(0,1)` —— 完全不含任何信息 —— 实测得到质量 0.6318 / 成本 12.19，而完美信号给出 0.7880 / 18.30。两个数相除：**即使信号是纯噪声，这套机制仍会花掉 66.6% 的成本。**反过来说，你的路由决定只直接驱动了 33.4% 的资源流向，其余三分之二由结构自身的默认形态决定。

### 失败的代价

代价有三层，越外层越贵。第一层是**质量债**：路由把本该用慢档的请求送去快档的那一刻，损失就已经发生，而且它没有堆栈、没有报错、没有重试点。返回的结果语法正确、语气自信、整体像一个答案。在本仓的合成世界里这类事件被称为「逃逸」（escape），定义为「走了快档，而慢档本可以答对且质量差超过 0.30」。在完美校准下逃逸率为 0；当模型过度自信（gamma=0.25）时，逃逸率升到 **15.7%**，同时整体质量从 0.7880 塌到 **0.5309**（-32.6%）——注意这个数字已经低于「永远用中档」的 0.5866：**过度自信的路由，比完全不路由更差。**第二层是**维护债**：三档意味着三倍的配置面。任何一次模型升级都要重跑三份回归，而重跑的动机在「看起来一直正常」的前提下会不断衰减。实验 7 给出分布迁移的证据：在一批「偏易」任务上调出来的最优阈值搬到「偏难」任务上，结果差别不到 0.004 —— 不是因为迁移鲁棒，而是因为**在偏难任务上两套阈值都退化成了全慢档**。「鲁棒」的读数掩盖了「失效」的事实。第三层是**认知债**，也是最贵的：一旦团队接受了「置信度路由能省钱」这个叙事，省钱的讨论就会被挪到「调阈值」上去。而实验 3 的结论是——在 140 个阈值组合里，能达到 Q≥0.80 的只有 30 个，这 30 个之间的成本差异只有 **1.13 倍**（19.93 vs 22.54），与此同时整个网格的**质量**极差高达 0.2816。结论是：**hi/lo 是质量旋钮，不是省钱旋钮。**想降本，要改的是档位之间的成本结构，不是这两个数字。



## 概念模型与术语

**档位（tier）** — 一组可以互换的执行资源，本仓用 fast / medium / slow 命名，它们各自带一个成本系数（1 / 5 / 25）和一条质量衰减曲线。档位不必是三个模型，也可以是「同一个模型的三种解码预算」——快档=贪心解码+短 CoT，慢档=多次采样+长 CoT。这个映射往往比换模型更实用，因为它避免了三份模型的版本地狱。

**置信度（confidence）** — 一个落在 [0,1] 的数值，声称代表「这次回答有多大概率是对的」。本仓对它只有一个要求：**与真实胜率单调相关**。注意是单调，不是准确。一个系统性乐观的置信度（永远比真实值高 0.2）在单调性成立时仍可能被好的阈值救回来，一个随机抖动的置信度则不能。

**双阈值（hi / lo）** — 把 [0,1] 切成三段的两个切点，是整个机制**唯二**的可调参数，也是本仓要重点讨论其有限性的地方。默认 0.8 / 0.4 无可追溯的标定依据，请当作占位符处理。

**逃逸（escape）** — 便宜档接了本该贵档做的活。损伤对象是用户。判定口径：走了快档，而慢档本可以答对且两者质量差超过 0.30。

**浪费（waste）** — 贵档接了便宜档就能做的活。损伤对象是账单。判定口径：走了慢档，而快档的质量已经超过 0.95。

**校准漂移（calibration drift）** — 模型输出的置信度与实际胜率之间的映射随时间变化。本仓用 gamma 参数模拟：gamma<1 表示过度自信。它是本仓识别出的**最大风险源**，其破坏力显著大于纯粹的估计噪声。

**零信息基线（zero-information baseline）** — 把 confidence 换成独立随机数后机制的表现。本仓测得 Q=0.6318 / C=12.19。任何自称「有效」的门控都必须先打败这条基线，否则它就是装饰品。

**Q / C** — 本仓的合成读数记号：Q = 平均答对概率，C = 每次请求的平均成本单位。两者都来自 bench_p03.py，**不含任何真实 LLM 调用**。

### 概念之间的关系

```text
confidence --经 hi/lo 切分--> 档位选择 --决定--> 单次成本 C 与单次质量 Q
档位的质量衰减曲线 --与难度分布共同决定--> 各档占比 mix
mix --加权--> 总成本 C        Q = 各档质量按其承接请求的加权平均
校准漂移 --抬高 confidence--> fast 占比上升 --> C 下降 且 逃逸率上升 --> Q 下降

★ 关键因果：任何让 C 下降的操作，都必然同时抬高逃逸率。
  C 和 Q 不是两个指标，是同一个权衡的两侧。这条因果链是理解本仓全部实验的钥匙。
```
