# P03 · 03-boundaries-and-alternatives

> 属于 [P03 confidence-gated-reasoning-switcher](../README.md) 的文档分册。


## 边界：该用 / 不该用 / 失效模式

### 适用条件（全部满足才用）

1. 存在至少三档可互换的执行资源，且它们之间的**成本比 ≥5 倍**（本仓合成模型用 1 / 5 / 25）
1. 各档之间存在**实质质量差**：本仓模型中 fast 的质量衰减速度是 slow 的 7.5 倍
1. 任务池的难度分布宽，且便宜档够用的那部分占比显著（实测低于 15% 时整套机制失去意义）
1. 上游置信度与真实胜率**同向单调**，且这个单调关系你至少每两周验证一次
1. 你能记录每一次路由决策与事后结果——没有这条，校准漂移永远不会被发现

### 禁用条件（任一命中就停）

1. **任务池偏难**：实验 7 中偏难分布下 98% 流量落 slow，固定质量口径下相对全 slow 只省 0.04%
1. **置信度从未校准**：实验 5 中 gamma=0.25 时质量跌至 0.5309，低于「永远中档」的 0.5866
1. **档位质量差 <5%**：路由沦为成本高噪声发生器；此时应改成单点执行 + 事后压缩
1. **单次调用计费且无法中途换模型**：一旦首档被选定就无法回头，会造成沉没的前半段成本
1. **合规场景要求统一档位**：金融、医疗等高风险场景下「这次用了便宜档」本身就是不可接受的解释成本

### 失效模式

| 失效模式 | 症状 | 处置 |
|---|---|---|
| 逃逸率抬头 | 正常应接近 0；合成世界里过度自信（gamma=0.25）时达到 15.7%，对应的整体质量从 0.7880 跌到 0.5309 | 每周用固定的 held-out 集重测 fast 档的真实胜率，偏离历史 >0.05 即触发重新标定 |
| fast 档占比异常上升 | 在分布稳定的前提下，占比从 8% 涨到 30% 几乎总是意味着自信度被抬高而非任务变简单 | 同时看占比与真实胜率两个数；只看占比会把「模型变自大」误读成「成本优化了」 |
| 成本下降但投诉上升 | 这两个信号同时出现即判定为逃逸，不是优化成功 | 把「逃逸相关的投诉」做成单独标签，不要混进一般满意度里 |
| 三档占比趋近 0/0/100 | 说明任务池已经超出 hi/lo 的分辨能力，机制在此分布上等价于不存在 | 直接降级为全 slow 并发告警；保留一个不工作的路由比没有路由更贵 |
| NaN 静默落入中档 | `pick(nan, 0.8, 0.4)` 返回 `"medium"`，无异常无告警 | 在调用侧加 `math.isnan` 与区间断言；这是本仓实测出的真实行为，不是假设 |



## 常见误用与反例

### 反例 1 · 用未校准的自评分数当置信度

**错法**：直接把模型回答的「我有多确定」（0-10）除以 10 当作 confidence，从不画校准曲线

**后果**：过度自信会把质量从 0.7880 拉到 0.5309，且整个过程账单更漂亮

**正法**：先在一批 held-out 样本上画出 calibration curve 确认单调性，再谈是否使用

### 反例 2 · 为让降本报表好看而逐步下调 hi

**错法**：放宽快档准入，直到逃逸率超过 10%

**后果**：平均成本的下降与用户体验反向，且这种反向最难被人发现

**正法**：把 hi/lo 当作**质量目标旋钮**使用：先在固定 Q 目标下求成本最优组合并锁定

### 反例 3 · 三档用同一模型的不同 temperature 却假设质量差 7.5 倍

**错法**：把解码参数的微调当成三个独立档位

**后果**：真实质量差远小于假设，导致路由在最该保守的地方冒进

**正法**：每一档用独立的 held-out 集测出它自己的质量曲线，用测出来的数据而不是假设填进决策

### 反例 4 · 用当天线上数据调阈值

**错法**：在没有 held-out 集的情况下按当天流量调参

**后果**：等价于用自己给自己出题，第二天分布稍动即失效，且表现为「随机波动」而非调错参数

**正法**：标定集与评估集互不相交，且评估集的时间窗口必须在标定集之后

### 反例 5 · 用返回值拼模型名

**错法**：`f"model-{tier}"` 这类写法

**后果**：档位拼写错误时静默落到默认模型，监控系统看到的仍是「档位都正常」

**正法**：用显式白名单校验：`assert tier in {"fast","medium","slow"}`

### 反例 6 · 扩展成五档却不动结构

**错法**：线性增长的 `if` 链

**后果**：顺序敏感性从无害变成致命；没有人能说清「为什么这个请求走了第三档」

**正法**：档位 >3 时改用显式区间表 `[(下限, 上限, 档位), ...]`，写成数据而不是代码

### 反例 7 · 流式响应中途换档

**错法**：在 SSE 已经走到一半时才发现要换档

**后果**：前半段已发送给用户，换档只会导致重复或断裂，用户可见的前后矛盾

**正法**：必须在生成首个 token **之前**完成路由，或明确接受「中途换档不可能」这个约束



## 与替代方案对比

诚实地说：本机制不是唯一解。下表列出常见替代，以及什么情况下该选它们而不是本仓。

| 替代方案 | 与本仓的核心差异 | 何时应选它 |
|---|---|---|
| 永远用最贵档（不路由） | 质量上界 Q=0.8261 / C=25.00，维护面最小。所有其他方案的收益都必须相对它来衡量。 | 成本高到无法接受之前，它其实是最省心的方案——尤其当你还没有证据证明 confidence 有效时。 |
| 永远用中档 | Q=0.5866 / C=5.00。本仓扫描了 medium 从 1× 到 10× fast 的全部取值，**三档门控在成本上从未赢过它**。这句话必须被理解为：只要中间档足够便宜且足够好，「永远中档」就是更简单的更优解。 | 当你有三个以上的档位资源却只有一个人维护时，先考虑这个方案。 |
| 软路由（expected-utility） | λ=0.012 时 Q=0.7684 / C=16.31。不需要调两个没有物理含义的阈值，λ 直接是「质量与成本的兑换率」。 | 当你**能测出每档的质量曲线**时选它——它的可解释性远好于 hi/lo。 |
| 两档门控（去掉中档） | Q=0.8191 / C=23.10。结构复杂度减半，质量反而更高，说明它与三档是同一条前沿上的不同位置。 | 档位资源有限的团队：两个一点 than 维护三个半成品。 |
| 思考预算分配（P02） | 同一个模型，给不同步骤不同思考预算，不换档不改模型。 | 当这一步**不能被隔离执行**时选它；能整体交付给另一个模型执行时才用本仓。 |
| 事后压缩（P04） | 不改变档位，只把已经生成的思考过程压短，解决的是「总量」而非「选谁」。 | **建议最先实施**：它在三者里收益最确定、复杂度最低。顺序推荐 P04 → P03 → P02。 |
| 按任务类别走专家路由 | 消费的是类别标签而不是一个浮点数，信息量大得多，路由质量上限更高。 | 当你能可靠分类时——它是本仓的上游依赖，不是本仓的替代品。 |

### 六维对比

| 维度 | 本仓 | 全用贵档 | 永远中档 | 软路由 |
|---|---|---|---|
| 维度 | 三档门控（本仓） | 质量上界，成本最差 | 极简折衷 | 需要质量曲线 |
| 质量 Q（合成、均匀难度） | 0.7880 | 0.8261（上界） | 0.5866 | 0.7684 |
| 成本 C（同上） | 18.30 | 25.00 | 5.00 | 16.31 |
| 相对全贵档节省 | 26.8% | 0% | 80.0% | 34.8% |
| 需调参数个数 | 2 个（无物理含义） | 0 | 0 | 1 个（λ，有单位） |
| 依赖的前置知识 | confidence 的单调性 | 无 | 无 | 每档的质量曲线 |
| 维护面（回归集份数） | 3 | 1 | 1 | 3 + 效用函数 |
| 任务池偏难时退化为 | ≈ 全贵档（省 0.04%） | 不变 | 不变 | ≈ 全贵档 |
| 校准漂移敏感度 | 高（gamma 1.0→0.25 致 Q -32.6%） | 无 | 无 | 高 |
