## 复杂度与实测性能

| 项 | 结论 |
|---|---|
| 时间复杂度 | O(1)：两次浮点比较，无循环、无分配。它是整套流水线里成本最低的环节之一。 |
| 空间复杂度 | O(1)。无状态、无缓存、无对象属性，可以被内联到调用方而不改变任何语义。 |
| 依赖 | 仅 Python 标准库，零第三方 |

### 实测

| 输入规模 | 耗时 | 备注 |
|---|---|---|
| 单次 `pick()` | 亚微秒级 | 在 n=4000 的完整评估中，路由本身消耗的时间远小于随机采样 |
| 实验 3 全网格扫描 | 约 56 万次决策评估 | 140 个组合 × 4000 任务。**这是本仓最大的隐性成本**，但它是一次性成本，不是每次调用成本 |
| 逃逸率观测下限 | n≥1000 才可读 | bootstrap（gamma=0.7、sigma=0.15）：n=50 时 95% 置信区间 ±214%，n=200 时 ±97%，n=1000 时 ±39%，n=4000 时 ±21% |
| 质量观测下限 | n=200 已可读 | 同一批 bootstrap：n=50 时 ±0.038，n=4000 时 ±0.0036。**平均值比低频事件容易测得多** |

> 测量方式与复现脚本见下节「可复现实验」。数字会随机器变化，**看数量级与增长趋势，不要记绝对值**。



## 集成指南（CLI / 库 / CI 三路）

### 路线一 · 命令行直接跑

```bash
python impl.py
# 输出: [P03] ['fast', 'medium', 'slow']
```

仓自带 `demo()`，输出即为 golden 值，CI 比对它就能发现实现被改坏。注意三个输入 0.95 / 0.6 / 0.2 分别落进三档，恰好覆盖了全部三条分支——这是一次有意设计的「路径全覆盖」冒烟，而不是随手写的例子。

### 路线二 · 作为库调用

```python
from impl import pick

MODEL_OF = {"fast": "gpt-mini",
            "medium": "gpt-mid",
            "slow": "gpt-large"}

def route(confidence):
    if math.isnan(confidence) or not 0.0 <= confidence <= 1.0:
        raise ValueError(f"bad confidence: {confidence!r}")
    tier = pick(confidence, hi=0.8, lo=0.4)
    assert tier in MODEL_OF, f"unexpected tier: {tier!r}"
    log_route(confidence, tier)   # 供下次标定使用
    return MODEL_OF[tier]
```

**注意这两道防线都写在调用侧而不是 `pick()` 内部**——这是本仓的定位决定的：`impl.py` 是规格参考实现，生产防线是你自己的责任。`log_route` 那一行也别省：没有它，校准漂移无从发现，而实验 5 已经证明校准漂移是本机制最大的单一风险。

### 路线三 · 接进 CI

```yaml
- name: 分档位回归（不得合并为单一总通过率）
  run: |
    for tier in fast medium slow; do
      python -m pytest tests -k "$tier" --tb=short
      # 任一档位独立通过率低于阈值即失败
    done
    python check  # 检查 (confidence, 正确性) 联合分布是否漂移
```

把「每档独立回归通过率」作为合并前的检查项，三个档位各自有一个最低阈值。这条比「整体通过率」重要得多，因为路由会让整体通过率掩盖**某一档独自崩掉**——而单档崩溃正是本机制最主要的失效形状。

**退出码约定**：`0` = 通过；`1` = 发现问题（CI 应失败）；`2` = 用法或环境错误（不是代码问题）。



## 可复现实验与验证协议

一个机制「有用」不是靠断言，是靠能被证伪。下面每个实验都给出**操作步骤 + 判定标准**，任何人可独立复跑。

### 实验 1 · 基线对照：全快 / 全中 / 全慢 / 门控 / 软路由 / ORACLE

对同一批 4000 个合成任务分别跑六种策略，读数见「替换方案」的六维对比表。其中 ORACLE 拥有**完美的难度信息**并按最省的方式选档，它的读数是 Q=0.8222 / C=23.08。

**判据**：**任何声称三档门控能把成本砍到一半的说法，都需要先解释它凭什么打败 ORACLE**——连全知选手也只能把成本压到全贵档的 92.3%。

### 实验 2 · 阈值网格扫描：hi × lo 共 140 组

hi 从 0.45 到 1.00、lo 从 0.05 到 0.70 全组合扫描，对每个组合评估全池。复跑命令：`python bench_p03.py`，见输出的「实验 3」。

**判据**：能达到 Q≥0.80 的组合只有 30 / 140，它们之间成本最多差 **1.13 倍**，而全网格的质量极差达 **0.2816**。判定：**阈值是质量旋钮，不是省钱旋钮。**

### 实验 3 · 公平口径对照：固定质量目标下谁最便宜（4b 与 4c）

给定 Q 目标，在阈值网格里找最便宜的组合，与「最便宜的可用单档」比较。在均匀分布（4b）与偏难分布（4c）各做一遍。

**判据**：4b：门控在 Q≥0.55/0.60/0.70/0.78/0.82 分别以 4.05 / 8.47 / 11.83 / 17.54 / 22.46 达成，始终优于当时的最便宜单档。4c：Q≥0.75 时门控 24.99 vs 单档 25.00，**只省 0.04%**。**收益几乎完全由任务池的难度分布决定，与机制本身的精巧程度无关。**

### 实验 4 · 信号解耦：保持源码不变，只替换 confidence 的来源

六组信号（完美 / 20% 噪声 / 纯随机 / 反信号 / 常数 / 恒定负偏移）喂给同一个 `pick()`，比较 Q、C 与档位占比。

**判据**：随机信号仍能花掉 12.19 / 18.30 = **66.6%** 的成本。**如果一个机制在完全没有输入信息的情况下仍能给出体面读数，那么体面的读数就不能证明它有输入信息。**

### 实验 5 · 校准漂移与估计噪声的分离 measurement

gamma 在 1.2→0.25 之间扫描（模拟从保守到极度自信），sigma 在 0→0.35 之间扫描（模拟纯粹的估计抖动），两者独立评估。

**判据**：gamma 从 1.0 到 0.25 使 Q 跌 32.6%；sigma=0.35 只使 Q 跌 7.4%。**漂移比噪声危险一个数量级，因此校正优先于降噪。**

### 实验 6 · 小样本稳定性：四档样本量 × 40 次重采样

在 gamma=0.7、sigma=0.15 的现实漂移条件下，对 n=50 / 200 / 1000 / 4000 各做 40 次 bootstrap。

**判据**：逃逸率的相对误差在 n=50 时为 ±214%，n=200 为 ±97%，n=1000 为 ±39%。**几百条数据得出的逃逸率结论基本不可信**——这条限制了谁能对这套机制下判断。



## 生产化改造清单

本仓是**最小参考实现**，刻意做小以便读懂。真上生产前，按优先级处理下列事项：

| # | 改造项 | 优先级 | 不做会怎样 |
|---|---|---|---|
| 1 | 输入范围与 NaN 校验 | P0 | `pick(nan)` 静默返回中档、越界值依赖比较语义、`pick(None)` 抛 TypeError |
| 2 | 返回值白名单校验 | P0 | 字符串拼写错误永不崩溃，只会静默走默认分支 |
| 3 | 每天重新标定 hi/lo | P1 | gamma 从 1.0 到 0.8 即损失 0.018 质量，静态阈值保质期可能短于发版周期 |
| 4 | 逃逸率告警而非平均值告警 | P1 | 平均值会掩盖单档崩溃：某一档崩了而另两档正常时均值只掉一点点 |
| 5 | 显式区间表替换 if 链 | P2 | 顺序敏感性在 3 档时无害，5 档时成为 bug 温床 |
| 6 | 冻结 held-out 样本库 | P2 | 没有固定评估集就无法区分「模型变强」与「任务变简单」 |
| 7 | 熔断到全 slow | P2 | 偏难分布下机制退化为全 slow 却不自知，白付维护成本 |
| 8 | 把 hi/lo 的来历写进配置注释 | P3 | 默认的 0.8 / 0.4 无可追溯依据，后代维护者会误以为它们被标定过 |



## FAQ

### Q：它到底能省多少钱？

在我们的合成模型里，相比「永远用慢档」省 26.8%（18.30 vs 25.00），代价是质量从 0.8261 降到 0.7880。**但这个数字不能搬到你的系统**：实验 7 显示换成偏难分布，节省只剩 1.7%，在固定质量口径下更只剩 0.04%。能省多少几乎完全由你的任务池决定。

### Q：为什么把置信度换成随机数，它还『能用』？

这正是实验 11 要问的问题。答案是：路由的输出分布主要由**结构**决定（三档各自承接多少份额），信号的强弱只在这个基础上做偏移。随机信号下它仍然要花掉 12.19 的成本单位，因为「三档 + 两个切点」这个结构本身默认会把流量铺开。**如果一个机制在无输入信息时仍能给出体面读数，体面读数就不能证明它有输入信息。**

### Q：这些数字是真实的吗？

不是。全部来自 `bench_p03.py` 里的**合成难度模型**：质量函数是 `exp(-decay·d)`，成本是人为设定的 1 / 5 / 25，难度来自均匀分布与 Beta 分布。**没有任何一次真实 LLM 调用。**它能支撑的是「机制的形状」和「参数的脆性」，不能支撑任何性能承诺。把这条写在这里，是因为省略它的话，上面所有表格都会变成谎言。

### Q：默认阈值 0.8 / 0.4 是怎么来的？

坦白说：它们是「看起来合理的两个数」，本 README 找不到任何可追溯到标定实验的依据。在合成默认分布下它们给出 8% / 24% / 68% 的占比，其中快档占比明显偏低。**请把它们当作占位符，并在接入的第一周用你自己的数据替换掉。**

### Q：中间档有必要吗？

在固定质量口径下，去掉中档的两档版本 Q 更高（0.8191 vs 0.7880）但也更贵（23.10 vs 18.30）。而实验 4 的扫描给出更刺眼的一条：**只要中间档足够便宜且足够好，「永远中档」会优于整套门控。**所以中间档的存在价值取决于它的性价比，而不是取决于「三档比两档更精细」这种直觉。

### Q：为什么不建议调阈值来省钱？

实验 3：140 个组合里能达到 Q≥0.80 的只有 30 个，它们的成本只差 1.13 倍，而整个网格的质量极差却有 0.2816。**阈值移动的主要效果是改变你落在质量轴上的哪一点，****而不是把你推离当前的成本-质量前沿。**想省钱要改档位之间的成本结构。

### Q：NaN 会怎样？

`pick(nan, 0.8, 0.4)` 返回 `"medium"`。因为 `nan >= 0.8` 与 `nan <= 0.4` 都是 `False`，于是落到兜底分支。它看起来像合理的保守降级，实质是**两次比较都失败后的意外结果**。`pick(None, ...)` 则会抛 `TypeError`。两者的不对称本身就是这个接口的设计缺陷。

### Q：校准漂移有多危险？

是最危险的一项。gamma 从 1.0 降到 0.8（仅仅是中等程度的过度自信），质量就从 0.7880 掉到 0.7700；降到 0.25 时掉到 0.5309，**低于永不路由的「永远中档」（0.5866）**。也就是说：一个足够自信的模型会把这套机制变成一个比不装更差的装置，而且全程账单更漂亮。

### Q：样本量要多少才敢下结论？

看你要测什么。测平均质量 Q，n=50 的 95% 置信区间是 ±0.038，n=4000 收到 ±0.0036。测**逃逸率**则严苛得多：n=50 时相对误差 ±214%，n=200 仍 ±97%，n=1000 才 ±39%。**几百条数据得出的逃逸率结论基本不可信。**

### Q：顺序对吗？先路由还是先压缩？

建议的顺序是：**先 P04（压缩总量）→ 再 P03（换档）→ 最后 P02（分预算）**。理由是三者的收益递减而复杂度递增：压缩解决的是「本不该生成的东西」，换档解决的是「生成者选错了」，分预算解决的是「给对了人但钱分错了」。跳过前两步做第三步，等于在浪费的基础上做精细分配。

### Q：它和 P02 的区别到底在哪？

一句话：**这一步能不能被隔离执行。** 能隔离成一整段、可以整体换一个模型去做 → P03；不能隔离、是流水线的一个环节 → 用 P02 给它更多思考预算。两者不是替代关系，在一套真实系统里它们通常同时存在，分别作用在不同粒度上。

### Q：什么时候应该删掉这个机制？

四个条件任一成立就删：① slow 占比 >90% 持续一周（已退化为全慢档）；② `confidence` 与真实胜率的等级相关 <0.3；③ 一个迭代周期内校准漂移 >0.1 且无法自动重标定；④ 三档之间的实测质量差 <5%。**删掉它是一种进展，不是失败**——它意味着你终于测出了环境的真实形状。

### Q：为什么写这么多否定自己的内容？

因为一个只讲优点、不讲适用边界的 README，读者无法判断它到底适不适用。本家族的旗舰仓 `emergent-mechanisms` 把「负对照是所有声称的前提」写进了评测协议：没有负对照的性能提升，与没有对照组的药物实验是同一种东西。
