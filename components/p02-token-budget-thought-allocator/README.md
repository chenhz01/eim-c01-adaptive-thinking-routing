## TL;DR — 60 秒判断要不要用

**一句话**：一道题里，有的步骤很难、有的很简单。这个工具把'想多久'的额度按难度分给每一步，难的多想、简单的少想。

**机制本质**：按每步不确定性归一化后分配思考预算：uncertainty 越大分配越多 token，总量守恒。

**怎么接**：allocate(uncertainties, total_budget) 返回每步预算列表；配合你的生成器逐段限额。

| 信号 | 判断 |
|---|---|
| 一次回答可以被切成若干「步骤」（子问题、检索轮次、工具调用、论证段），且每步可单独限额 | ✅ 该用 |
| 各步的难度差异很大，且存在明显的「不该投太多」的步骤（饱和、无信息量、有外部兜底） | ✅ 该用 |
| 你已经有办法对每步给出一个「不确定性」数值（哪怕很粗），并且能对生成器逐段设上限 | ✅ 该用 |
| 瓶颈是「总 token 预算固定，要在若干步之间分」——而不是「整体预算怎么砍」 | ✅ 该用 |
| 单步作答、无法切分的任务：没有「分配」这件事，本仓退化为常数 | ⛔ 不该用 |
| 各步之间存在强依赖（后面的步要看前面的步才能产生），静态一次性分配会按错的顺序下注 | ⛔ 不该用 |
| 你的不确定性估计是拍脑袋的常数（例如一律 0.5）：此时比例分配等于均分，却多了一个故障面 | ⛔ 不该用 |
| 真正的问题在「整体太长」而非「比例不对」：先做裁剪（P04）/ 早停 / 降模（P03），别先做分配 | ⛔ 不该用 |



## 问题：它到底在解决什么

### 真实场景

一次复杂回答通常不是一口气想出来的，而是由一串步骤组成：① 澄清题意；② 检索或查表；③ 建立中间结论；④ 处理反例；⑤ 汇总。给这套流程一个固定预算，比如 1,200 个思考 token。最自然的分配是「谁难谁多拿」——把 uncertainty 归一化后按份钱。本仓就是把这句直觉写成 6 行代码：`allocate(uncertainties, total_budget, floor)`。它在纸面上无懈可击，在实现上零依赖，在接口上三步可接。问题是：当我们真把它接上去、用可控的收益曲线去量化它的效果时，**它在最常见的那类收益曲线上输给了「每步一样多」。**这不是书写错误，是下面「 TL;DR 之后」要用三个实验解释清楚的结论。本仓的价值因此不在于「给你一个分配器」，而在于「把分配这件事做错的成本量化出来」。

### 朴素做法为何失败

朴素做法有两层，第一层是「均匀」：把 1,200 平均分给 8 步，每步 150。它的缺点一眼可见——简单的步骤拿到的预算远超它需要的（饱和浪费），难的步骤拿到的远低于它需要的（永远做不完）。于是第二层「按难度分」登场，这正是本仓实现的东西。但这里藏着一个几乎没人检查的跳跃：**「难」不等于「多投入划算」。**如果一步的难度是 τ=600（意味着要 600 token 才学会它的六成），那么它的边际收益是 (1/τ)·e^{-b/τ} —— τ 越大，每多投一个 token 换来的收益反而越低。把预算按难度比例倾斜，等于把钱优先投给边际收益最低的地方。反直觉，但它直接来自收益饱和这个事实，而不是来自某种悲观假设。实测：在 n=8、τ 从 40 到 600、B=1200 的配置下，按难度比例分配的总收益 4.006，均匀分配 4.621 —— **朴素第一层赢了第二层，领先 13.3%**。

### 失败的代价

代价同样分三层。第一层是直接的收益损失：上面那个 13.3%，它可能就是「这题能不能答对」的差距，而且它**不会出现在任何日志里**——系统看起来在正常工作，预算花完了，答案也出来了，只是答案比原本可以得到的差一点。这种损失没有告警、没有报错、没有回滚点。第二层是调试成本：因为「按难度分配」在直觉上绝对正确，团队会先去调 τ 的估计、调 prompt、换模型，唯独不会怀疑分配公式本身。我们把这条路径称为「正确答案的暴政」——越正确的直觉，越难被质疑，因而一旦出错，排查时间越长。第三层最贵：**它会传染。**一个被验证「有效」的分配公式会被复制压到检索预算、压到并发 budget、压到多智能体的轮次分配，每复制一次，那个错误的比例假设就被继承一次。到这一步，修的成本已经不是在改公式，而是在改大家的共识。



## 概念模型与术语

**思考预算（thought budget）** — 允许某一步消耗的最大推理 token 数。注意它是「上限」不是「目标」：真正花掉多少取决于生成器，分配器只负责分段设限。把上限当目标会导致「凑字数式思考」。

**不确定性（uncertainty）** — 本仓唯一的输入信号，表示「这一步有多不确定的正整数或正实数」。它必须来自某种外部观测（草稿分歧、熵、历史正确率、规则命中），不能来自模型自评——自评置信度的校准误差会直接叠加在分配误差上。

**比例分配（proportional allocation）** — b_i = B × u_i / Σu。本仓的本体。它是最简单的满足「单调性」的分配：难的多、易的少。它隐含一个从未被写出来的假设：**收益对投入成正比**。

**保底（floor）** — 每步至少拿到的预算。它的作用是防止某一步被判「确定」后拿到 0，从而彻底失去纠错机会。代价是破坏总量守恒——实测 n=32 时总预算被抬到 1.60 倍。

**总量守恒（budget conservation）** — Σb_i = B。这是所有预算机制的隐含契约：分配器只挪位置，不印钞票。本仓在 floor 生效时会破约，这是设计取舍而非 bug，见决策 3。

**饱和（saturation）** — 再投入也不涨的那一段收益曲线。它是「为什么难的步骤不该按比例多拿」的全部原因：饱和意味着边际收益递减，而边际收益递减意味着「平均主义」在某些区间反而是最优的邻居。

**边际收益（marginal return）** — 多给一个 token 换来的额外收益。分配问题的唯一正确视角：**不是问「谁难」，而是问「下一个 token 给谁最值」。比例分配从不问这个问题，它只看起点难度。

**收益曲线的形状（return shape）** — 投入 → 产出的函数形态，是本仓的决定性变量。三种典型：饱和型 1-e^{-b/τ}、线性型 min(1, b/τ)、阈值型 min(1, (b/τ)²)。同一份难度在这些形态下的最优解完全不同，实测见实验 7。

**τ（难度尺度）** — 让某一步达到约 63% 收益所需的 token 数，是本文衡量「难」的方式，因为它把「难」翻译成可以被预算比较的单位。τ 大 = 难。

**预算充裕度（budget adequacy）** — 总预算相对于总难度的比值。它是本仓最重要的运行期指标，因为**谁赢由它决定**：实测预算极度稀缺时比例分配领先 9.0%，中等时落后 13.3%，充裕时又领先 2.5%。

**赢家通吃（winner-take-all）** — 把全部预算给最不确定的那一步。它是比例分配的极端形式，实测在全部三种收益形态下都是最差策略（收益 0.865 / 1.000 / 1.000，对比最优 4.74 / 6.68 / 6.48）。

**分配器 vs 生成器（allocator vs generator）** — 本仓是分配器：它输出一串数字。真正「花」掉预算的是生成器。两者的契约是 max_tokens / 软截止 / 停止条件，契约失效时分配器形同虚设（见边界第 4 条）。

### 概念之间的关系

```text
        ┌──────────── 分配给「下一个 token」的唯一正确问法 ────────────┐
        │                                                            │
        ▼                                                            ▼
   [ 观测每步不确定性 u_i ]                    [ 收益曲线 step_gain(b, τ_i) ]
        │                                                            │
        │  归一化 u_i / Σu                                            │ 形状决定边际
        ▼                                                            ▼
   b_i = B × u_i/Σu  ──►  max(floor, b_i)  ◄──  τ_i 大 → 边际低 → 少给
        │                        │
        │                        └─► floor 抬升 ⇒ Σb > B（守恒破约）
        ▼
   [ 生成器逐段限额 ] ──► 实际花费 ≤ b_i ──► 记录每步实花/产出
        │
        ▼
   监控：预算充裕度 = B / Στ    ← 决定「比例」还是「均匀」更优的那个量
```



## 机制原理：逐步拆解

### 步骤 1 · 把一次回答切成若干可独立限额的步骤

这是全部后续的前提，也是没有任何代码能替你做的部分。「步骤」的粒度决定了一切：切得太粗，分配失去意义（只有一两笔）；切得太细，每步拿到的预算低于最小有用思考单位（floor 被迫抬升，见步骤 4）。经验判据：**一步应该大到「单独投 50 token 就有非零收益」，小到「它的失败不会拖垮别的步」。**本仓不检查这一点——它是纯函数，只看你喂进来的列表长度。

### 步骤 2 · 为每步取一个可比较的不确定性值

`uncertainties` 是一个数字列表，可以是草稿一致性（P01）、检索命中率、历史正确率的补、也可以是人写的先验。这一步的**质量要求**远高于它的代码位置所暗示的：它是唯一的输入。实测（实验 3）显示，当不确定性估计的对数噪声 σ 从 0 涨到 2.0，按比例分配的收益从 4.006 掉到 3.681（-8.1%），而理论最优策略从 4.740 掉到 3.701（-21.9%）——**噪声越大，「更聪明」的分配越不值钱**。这条结论的外推是残酷的：在估计很脏的现实环境里，追求分配最优性几乎没有回报，更值得投入的是把估计做干净。

### 步骤 3 · 归一化并按份钱：b_i = B × u_i / Σu

一行实现：`int(total_budget * u / s)`，其中 `s = sum(uncertainties) or 1.0`。那个 `or 1.0` 是一处防御：全部为 0 时不做除法，但**它不是正确的处理**——全零意味着「没有任何不确定性信息」，此时比例分配没有依据，理论上应该返回均分或报错。参考实现返回每步 `floor`（实测 `allocate([0,0,0,0], 1000, 50)` → `[50, 50, 50, 50]`，花掉 200 token 买一个「我什么都不知道」的均匀下注）。见 FAQ Q5。

### 步骤 4 · 加保底：max(floor, b_i) —— 以及它悄悄打开的预算缺口

保底的善意是「给每步一次机会」。它的代价写在实验 1 里：当步数 n=32 且不确定性均匀时，总支出变成 1.60 倍预算；n=64 时 **3.20 倍**；长尾分布下更差，**3.55 倍**。原因是 max() 是单向的：它把低于 floor 的抬上来，却从不把高于的压下去。所以每多抬一点，总量就多一点，没有任何机制把它拉回 B。这是一个**必须被显式监控**的破约：见边界第 2 条与「生产化改造清单」第 1 项。

### 步骤 5 · 把每一份预算交给生成器，并记录实花/产出

分配器到这里就结束了，但它产生的真正资产是**留下来的那行日志**：`(step_id, u_i, b_i, 实花, 产出)`。没有这行日志，你永远不知道「比例 vs 均匀」在你的真实任务上谁赢；有了它，你可以用实验 9 的方法直接在自己的分布上测出交叉点。换句话说：本仓作为代码几乎免费，它作为**测量协议**才有价值。

### 为什么这样切分

为什么按「不确定性 → 归一化 → 乘预算 → 保底」这个顺序切？因为它保证了一条性质：单调性。理论上 u 更大 ⇒ b 不小。单调性是这类机制能被信任的最低要求。但请注意这条设计只回答了「难的是不是多拿了」，没回答「多拿是不是划算了」——后者需要收益曲线，而收益曲线不在这 6 行代码里，也不在任何一个零依赖的分配器里。把这两个问题分开到「它们不该在一起」的程度，正是本仓想传达的第一个机制设计教训：**分配器的接口应该比它的公式重要。**如果你换掉了 allocate 的实现（改成均匀、改成 water-filling、改成按边际收益逐份发放），调用方一行都不用改——这个接口形状才是值得抄走的部分。



## 代码逐行导读

本仓实现只有 `impl.py` 一个文件，全部逻辑可在一屏内读完。下面按执行顺序拆。

### 1. 片段

```python
def allocate(uncertainties, total_budget=1000, floor=50):
```

签名就是全部契约：一份不确定性、一个总额、一个保底。注意它**不知道** cost —— total_budget 是调用方的责任。这个设计让函数保持纯：同样的输入永远同样的输出，可以直接写单元测试，也意味着它无法「审预算不够就自动加」，那是策略，不该藏进工具里。

### 2. 片段

```python
    if not uncertainties: return []
```

空输入返回空列表而不是报错。这是「静默通过」的一种温和形态：调用方拿到 [] 会正常继续下游流程，仿佛「没有步骤需要预算」。如果你的流水线里 `steps` 有时为空是因为上游抽取失败，这里会把失败吃掉。生产用法见「生产化改造清单」第 6 项：把空输入变成显式异常或降级路径。

### 3. 片段

```python
    s = sum(uncertainties) or 1.0
```

归一化分母。`or 1.0` 处理 sum 为 0（包括全零与空列表之后的兜底）。它掩盖了两种情况：真的全零（无信号），与正负相抵恰好为 0（信号错误）。后者在真实系统里更常见也更危险——**负数不应该出现在这个接口里**，但实现不检查：`allocate([-1.0, 2.0], 1000, 50)` 返回 `[50, 2000]`，总额变成 2050，是预算的两倍，而且没有任何警告。

### 4. 片段

```python
    return [max(floor, int(total_budget * u / s)) for u in uncertainties]
```

一行完成三件事：按比例、取整、保底。顺序很关键——`int()` 在 `max()` 之前（先截断损耗再抬底），这和「先抬底再截断」在数值上略有差异，但更重要的是它们都**不可逆**：抬上去的总额再也回不来。`int()` 截断本身也有约 n/2 个 token 的整体损耗（实测 B=1200 且 floor=0 时总额 1197），这是可接受的，但要知道它不是精确守恒。

### 5. 片段

```python
def demo():
    print("[P02] budgets:", allocate([0.9, 0.1, 0.5, 0.2], 1000))
```

打印 `[529, 58, 294, 117]`（和为 998）。这是仓自带的冒烟用例，也是 golden_output.txt 的内容：CI 里拿它比对即可发现实现被改坏。把它留在 README 里的意义不是示范，是**把「可验证」变成默认**：任何人 clone 下来三秒就能确认这堆东西真的会跑。



## 设计决策与权衡

每一条都是**有代价的选择**，不是无争议的最佳实践。列出被放弃的选项和反悔条件，是为了让你在场景变化时知道该改哪里。

### 决策 1 · 用比例而不是求解

| 项 | 内容 |
|---|---|
| 备选 | ① 比例 b_i=B·u_i/Σu（选）；② 均匀 B/n；③ 拉格朗日最优（water-filling）；④ 贪心「每份给边际收益最高的步」 |
| 选择 | ① 比例。它零依赖、单调、可解释，几行代码足以让人看懂并推翻。 |
| 代价 | 在最常见的饱和型收益下，它的收益 4.006 低于均匀 4.621（-13.3%），也低于理论最优 4.740。 |
| 何时该反悔 | 当你测得自己的收益曲线属于「线性型」且预算充裕时，改用水的注水式；若你在 README 实验 9 的位置发现自己的预算充裕度落在 800–2400 的中段，应直接改用均匀。判断方法写在「可复现实验」第 9 个。 |

### 决策 2 · 保留 floor 保底

| 选择 | ② 固定保底 50 token。让再确定的步骤也保留一次纠正的机会。 |

## 第一性原理：它依赖哪条不可再分的假设

把本仓剥到不能再剥，只剩一句话：**稀缺的下一单位资源，应该流向「下一个单位能换到最多收益」的地方。**「按难度分配」之所以流行，是因为它把这句话里的「下一个单位的收益」偷换成了「这一步有多难」——两个在不同的世界里才相等。本 README 的全部内容，都是在把这个偷换拆开给你看。

### 底层假设：收益对投入单调递增且 concave（边际递减）

本仓实验所依赖的收益模型是 `gain = w·(1 - e^{-b/τ})`：单调保证「多给不会变差」，凹保证「多给的增量越来越小」。这两条都不是假设出来的审美，而是绝大多数 token 密集型任务的经验形状——第一步思考带来最多信息，第二十步思考带来最少。在这个前提下，「难」=τ大，而 τ 大同时意味着**起点的边际收益 (1/τ) 更小**。于是一句话就得出结论：按难度倾斜，等于按边际收益的反方向倾斜。

### 去掉凹性会怎样：线性世界里比例又对了

把收益换成线性型 `min(1, b/τ)`，边际收益在饱和前是常数 1/τ —— 它仍然随 τ 递减，所以凭直觉得出的结论依旧不成立：实测线性型下比例 5.452 仍劣于均分 5.726。真正的翻转发生在另一个维度：预算充裕度。当 B 大到足以让多数步越过各自的 τ，不同策略之间的分配差异就会被压缩，比例与均匀的差距收敛到 3% 以内（实测 B=9600 时 7.946 对 7.784）。所以：**凹性不是唯一变量，充裕度是同等重要的第二个变量。**

### 推导链：从「往哪投」到「下一步给谁」

正式地，最优解满足 KKT 条件：对所有获得正预算的步 i，`∂gain_i/∂b_i = λ`（同一个拉格朗日常数），而得不到预算的步满足 `∂gain_i/∂b_i ≤ λ`。这是一个「水位线」刻画：把所有步骤看成不同粗细的容器，注水直到边际收益被拉平。**注意这个刻画里没有出现「难度」这个词**——τ 只在决定容器形状时才间接进入。比例分配连容器形状都不看，只看容器的标签。

### 为什么这个偷换能流传这么久

因为它在三个层面上都是「看起来对的」：① 语义上，「难」和「需要更多资源」在日常语言里几乎同义；② 政治上，「给难的多」比「干脆不给难的」听起来更负责，后者听起来像放弃；③ 工程上，比例实现只要一行，而拉格朗日要估计 τ。三条加起来构成一个几乎无法被推翻的默认值。**要推翻它，必须拿证据而非逻辑——本仓的十个实验就是那份证据。**

### 更不可再分的一层：没有免费的新信息

任何预算机制都只做两件事之一：① 用已有的外部信息预测哪里的收益高；② 边投边观测，把后面的钱挪到实际产出的地方。②需要回收闭环（本仓静态分配做不到），①需要干净的输入。所以「零开销零信息还静态」的预算分配，在信息论上不存在优于均匀的一般性保证。这是一条下界：**本仓能赢，是因为你的输入（不确定性）携带了真实信息；输入的信息量锁死了它输出分配质量的上限。**

> 承认局限，也承认价值：本仓不保证最优，它保证的是「把收益分配这件事摆到桌面上」。认识到稀缺资源的正确流向由边际决定、而非由标签决定，你已经拿到本机制九成的收益。



## 反事实推演：六个「如果反过来」

反事实是成本最低的思维实验。下面五个里，有两个会立刻改善你的系统，一个会暴露本仓的伦理后果，还有一个会证明「什么都不做」有时才是正确答案。

### 若反过来：给最确定的步骤最多预算

表面荒谬，实际有意义——最确定的步骤往往 τ 小，边际收益 1/τ 大，给它更多 token 能迅速把它推到满分。极端形式就是「先喂饱便宜的」，也就是实验 4 里水到渠成的那个最优解：把 7 个 τ=30 的步骤喂到饱和，总收益 7.204，远超给唯一 τ=900 的步投 1200（赢家通吃，0.736）。同一条判据还有更锋利的用法：砍掉一条长期失败的业务线，与把 τ=600 的步骤预算置零，在数学上是同一个决定。这个反事实的意义不是建议你反向分配，而是让你看清：**「贵的学习目标」和「值得的学习目标」是两件完全不同的事。**

### 若不做：保持均匀

这是必须被认真对待的第一基线。在实验 9 的中段区间（B=800–2400，满足率 12%–38%），比例的收益比均匀低 5.7%–13.3%。如果你在这个区间且已经上线了比例分配，**关掉它立刻提升性能**——这是本 README 里唯一一条「可以立刻执行」的建议。补一句更直接的：对照实验的成本低到可以忽略——同一批样本各跑一次，问题就从争论变成了报表。凡是能被报表回答的问题，都不该停留在争论层面。

### 若做过头：KKT 求解 + 在线重算 + 按实花再分配

把每步的 τ 估计出来、实时解拉格朗日、每完成一步重算剩余。上限是最优解的 4.740（对比例 4.006，+18.3%）。但实验 3 给了致命的一刀：当估计噪声 σ=2.0，「按噪声解出来的最优」掉到 3.701，几乎与按比例的 3.681 打平。**追求最优性的收益，会被估计噪声全部吃掉。**这条结论外推到其他所有「优化昂贵的 + 估计脏的」组合上同样成立。

### 若只做一半：有分配但没有实花回收

静态分配把 1200 一次性发完，某步只花 20，剩下 130 就被冻在原地。实测偏差系统性超过 30% 就该改成两段式（生产化清单第 3 项）。这个反事实揭示了一类通用的半成品风险：**机制的价值常常不在它的公式，而在它的闭环。开了环的机制，性能上讨不到便宜，只为调试增加难度。**

### 若把它用在人身上：给「能力弱的同事」分配更多工作

这是同一套逻辑越界到人的后果，也是最值得停下来想一分钟的反事实。如果「强」对应的是「τ 小，投一点就见效」，那么给人分配工作的正确逻辑恰恰相反。但在很多组织里，「给难的更多资源」的直觉被机械地平移到了人身上，结果是把最难、最饱和的任务压给最需要练手的人。这个反事实提醒：机制的每一个假设，都有一个人身版本。**

> 记下最有操作性的那一条：在系统上线前先跑实验 9 的扫描，确认你的预算充裕度不在「 0.867」那个坑里——这一步的收益，大于任何参数调优。



## 跨域同构：它在自然与工程中的同形物

一个机制如果能只在一个领域成立，它多半只是那个领域的方言。下面四组同构里，最后一组「哪里不同构」往往比前三组更有信息量。跨域类比的价值不在修辞，而在于它把别的领域已经犯过的错借给你：你没有时间亲自踩的那些坑，别处通常早就有人替你踩过并留下了记录。

### 生物：代谢预算与「贵的器官」

人体给大脑约 20% 的能量，不是因为大脑「难」，而是因为每单位葡萄糖在大脑里换来的生存收益高于在别处——**正是边际收益视角，而不是难度视角**。同理，人体在饥饿时会优先保血糖而非肌肉合成：前者边际生存收益高，后者在长期才兑现。演化给大脑更多能量，从来不是因为它「难」——而是因为每一份葡萄糖在那里换来的生存收益最高。如果按「难度」分配，人体应该优先维持最难维持的组织，而那通常是收益最低的。

### 经济：资本预算与内部收益率

公司给部门分配资本的经典错误就是「按部门规模」或「按部门的困难程度」，正确做法是看每个项目的边际资本回报。一个负债累累的部门往往既「难」又「边际回报低」——继续注资是典型的沉没成本陷阱。实验 8 里最难一步拿到 0 预算，就是这条管理原则的数学版本：**承认某个目标在当前资源约束下不可达，然后止损，是资源分配的核心能力。**

### 军事与医学：分诊（triage）

战场与急诊的分诊把伤员分成「立即救治 / 可等待 / 姑息」三类，而这个分类依据的并不是「伤得多重」，而是**「投同样的资源能救回多少」**。最重的伤员（黑标）恰恰被放弃，正如 τ=600 的步骤在最优解里拿到 0。这个类比的价值在于：它证明「不给最难的多给」并非冷酷的工程妥协，而是所有稀缺资源领域共同收敛到的成熟做法——**工程只是最后才学到它。**

### 哪里不同构：当收益曲线未知时，跨域移植会出错

以上三个领域都有一个共同前提：历史数据足够多，收益曲线大体已知。而 LLM 推理预算的场景里，τ 常常既估不出来也不稳定。**这就是近年最危险的越界：把「投资/分诊」的成熟直觉拿过来，却少了它们赖以成立的那条测量基础。**本 README 之所以把十个实验全部开源，正是为了让这条移植至少有一个可测的着陆点。

> 同构的部分是「按边际分配」这个原则；不同构的部分是「你是否真的知道边际」。前者可以跨过领域直接借用，后者必须每个场景重新测量。把两者混为一谈的经典症状，是拿另一领域的成功经验为自己的懒于测量辩护。



## 失败考古：同类尝试的墓志铭

如果只流传 ──或许三个墓志铭，我们对失败的态度就是错的。下面三块碑，分别刻着「Theranos 式的单点豪赌」「德尔菲式的过度自信」和「所有 automl 的超参分配」。它们的共同死因，以及我们如何避免只看到它们。

### 墓志铭一：把所有预算押在「最难的一环」上

无数产品的失败源于此：团队认定「我们的核心难点是推荐算法」，于是把 80% 的工程资源压上去，而注册流程、加载速度、错误提示这些「τ 很小、投入几十个 token 就能满分」的环节长期得 0 分。最终用户从未越过登录页。这与实验 4 的赢家通吃完全同构：给 τ=900 的步投满 1200，总收益 0.736，而喂饱 7 个便宜环节可得 7.106。

### 墓志铭二：把「我看得很准」当成资源充足的理由

本世纪头十年的对冲基金喜欢用自评的置信度做杠杆——「我们对这笔交易有 95% 把握」于是加十倍杠杆。结果与 P02 的 Q7 警示完全一致：自评置信度在最危险的样本上最自信，杠杆在最需要收缩的时候被放大。换成分配器的语言就是：`u` 的输入本身带方向性偏差，下游的分配越精确，这个偏差被兑现得越彻底。

### 墓志铭三：超参数搜索中的「按直觉分配试验次数」

AutoML 早期常见的做法是让专家指定每个超参的重要性权重，再按权重分配试验预算。事后复盘发现，专家权重与实际重要性的相关性经常接近 0，而「每个超参都试一遍」的朴素策略反而更稳。这就是本 README 实验 2 的方法学祖先：**「troll身体的重要性 > 估计的重要性」——当你不清楚边际时，广度优于深度。**

### 共同死因：把「听上去有理的判断」当成「已测量的事实」

三块碑的共同点不是贪婪，而是**把未经校准的直觉当作输入信号喂进了一个精确的系统**。精确的系统会忠实地放大输入的偏差，且因为系统本身「工作正常」，没有任何环节会报警。这条死因在 LLM 工程里正在被大规模重现。

### 幸存者偏差：我们听不到那些「什么都没做」的成功

没有失败故事的东西确实存在：它们只是保持均匀、保持简单、保持可预测。一个从不做动态分配的系统，几乎不会上事故复盘会，也几乎不会写进博客。**你读到的一切关于「智能分配」的成功故事，都已经过了幸存者筛选。**把这条铭记在心，比记住任何一个公式都重要。

> 还有第四块没有碑、却更常见的失败：失败以「最佳实践」的形式复活。每当行业忘记一次负实验结果，它就会在下一代技术栈里被重新发明一次——本仓的实验 2 与 1990 年代的超参分配就是一次这样的重演。三个墓志铭合起来指向同一个动作：**在相信任何分配之前，先要一份对照组的数字。**本仓的十个实验，就是那份对照组的模板。



## 自我反驳：站在反方最强处攻击自己

这一章要站在最强的反方立场攻击本仓。不是 straw man——下面列的是我能想到的、最难反驳的批评，然后逐条让步。

### Steel-man 最强反方：你用一个假曲线否定了真机制

最强的批评是这样的：「你的全部结论都建立在合成收益曲线上。真实 LLM 的思考收益可能是**阈值型甚至阶梯型**——达到某个思考长度之前几乎无收益，越过阈值后突然可用。在这种世界里，把预算凑够阈值恰恰是最优策略，而你的实验 7 用的阈值型是 (b/τ)²，是光滑的，并非真实的硬阈值。」

### 承认成立的部分

这条批评成立。而且我愿意承认更多：**如果收益是硬阈值型（b<τ 恒为零收益），**那么「把难步骤凑到 τ 以上」确实优于均匀，那时的正确策略更接近「集中攻克」。本 README 无法排除真实 LLM 存在硬阈值的可能。我能给的只有两点回应：① 实验 7 已经把「曲线形状一变、胜负就翻转」摆到明面上——我只是人为地变化曲线形状，结果很敏感」这一事实摆出来了，读者可以自己替换收益曲线重跑；② 即使存在阈值，**识别阈值的成本**本身也是预算的一部分，而这笔成本在任何静态机制里都不被计入。

### 第二条反方：你在用玩具场景否定工程实践

第二条批评：「n=8、B=1200、τ∈[40,600] 是编出来的。真实系统里预算常常充裕到所有步骤都能饱和，那时谁优谁劣根本不重要，而读者会因为你的标题以为『不要用比例分配』。」这条也部分成立：实验 9 的 B=9600/20000 两行确实显示两者趋同（差 1%–2%）。但注意这句话恰恰证明了**充裕度是决定性变量**——而这正是本仓要传达的判断框架。

### 第三条反方：你把一个简单的东西写复杂了

「六行代码需要两万字吗？你只是在制造信息负担。」这条我只能部分承认：确实存在「用篇幅冒充深度」的行业陋习。我的辩护是**可证伪性**：本 README 的每一章都给出具体判据或具体数字，你可以逐条验证；若某章只剩下形容词，请把它当作失败案例提 issue。篇幅本身不是价值，**可被反驳才是价值**——这是本家族所有 55 个仓共享的第一写作原则。

### 剩余防线：三条不妥协的判断

退到只剩三条我还愿意辩护：① **依赖输入的策略，其价值上限由输入质量决定**（实验 3，σ=2.0 时最优塌了 21.9%）；② **存在一个系统性地决定『谁赢』翻转的区间**（实验 9，0.867 到 1.090 的跨度），因此「默认用哪个」这个问题必须有测过的答案；③ **最值得学的是接口而不是公式**——把 `allocate` 换成任意函数，调用方一行不动，这个性质比公式本身值钱。这三条都不依赖我对收益曲线的假设。

> 最后的诚实：如果有一天真实数据证明「硬阈值 + 充裕预算」是常态，本 README 关于「别用比例」的段落就应该被删除。**一个有删除条件的文档，才是活的。**



## 认识论：凭什么相信它有效

「凭什么相信它有效」是这一章唯一的问题。答案分三层：哪些证据类型是硬的、哪些是软的、哪些干脆不属于证据。把这三层分清，比记住任何一个数字重要。

### 硬证据：可跨机器复现的实测

本 README 中所有标为「实测」的数字，都出自 `deep/bench_p02.py`，换机器重跑应得到一致的数量级：同一份 n、τ、B 下四种策略的排序稳定，floor 超支倍数稳定，单次耗时随 n 线性。这类证据的特点是：**它不告诉你现实会怎样，它告诉你这套代码在你的机器上会怎样。**它们的价值在于完全可复现——任何人都能在三十秒内证伪。

### 软证据：合成收益曲线的结论能否外推

所有关于「谁赢」的结论都建立在假定的收益曲线上，这是本仓最大的软肋。诚实做法是标明**结论对曲线形状的敏感度**：实验 7 显示在同一份难度下，只换曲线形状就能让最优值剧烈变化（4.740 / 6.682 / 6.476）。所以正确读法是：把本 README 当作**一台可编程的天平**——你把真实曲线喂进去，它告诉你答案；它本身不提供答案。

### 失效边界：它在什么条件下明确不成立

三条明确失效：① **硬阈值型收益**（达到之前毫无产出）：此时「集中攻克」可能优于均匀，本仓「别用比例」的结论失效；② **步骤间强依赖**（后面的步骤需要前面的产出）：静态分配失去意义，本仓连问题定义都不成立；③ **不确定性 u 与目标内生相关**（例如 u 取自同一个模型的自评）：此时任何「按 u 分配」都是在自我背书，而不是在测量。这三条应该被写进你的上线检查表。

### 可反驳的形式：一句话可以被什么推翻

本仓最核心的那句「预算应按边际收益而非难度分配」，可以被这样一个实验推翻：在同一份 n 与 τ 下，若**比例分配在多数真实任务上的实测收益显著高于均匀**，且差异不被噪声解释，则本结论错误。注意它定义了推翻它所需的全部要素——这就是可证伪性：**不是因为我说得谦逊，而是因为我说得具体。**

### 认识论上的一个陷阱：加粗的数字会让人不去检查来源

本 README 有很多加粗数字，这本身就是一种风险：加粗伪装了确定性。防这个陷阱的机制很简单——**每个加粗数字后面必须跟着「怎么重跑」**。读者可以随手抽三个数字验证；只要有一个对不上，整份文档的可信度就该被下调。我把这条写成明文，是为了让它可以被用来攻击我自己。

> 证据分级：可复现 > 可复算 > 可类比 > 可引用 > 好听。本 README 尽量停在前三档；凡你看到第四、第五档的地方，请以随时可被推翻为默认态度。



## 规模律：10× 与 100× 时先坏在哪

规模律回答「事情变大会怎样」。本仓在 10× 与 100× 时坏的地方不同，而这两处恰好都由同一个参数引发——floor，那个看起来最不起眼的默认值 50。

### 10×：步数从 8 到 80

最先崩的不是正确性，是**会计约束**。实验 1 已经给出：n=32 时总额 1.60 倍，n=64 时 3.20 倍，长尾 3.55 倍。原因是 floor 是绝对量（50 token）而预算是总量，两者随 n 增长的关系是 n×floor 对 B —— 必然交叉。二阶后果更麻烦：一旦团队习惯了三倍的实际支出，预算表本身就失去意义，任何「我们花了多少」的讨论都建立在错的基数上。会计失真比性能损失更难修复，因为它污染的是决策的输入，而不是答案的质量。前兆指标：`sum(allocate(...)) / B` 单调上升；建议超过 1.2 时告警。

### 100×：分配到上千步的分片流水线

此时另一个东西会崩：**不确定性之间的可比性**。在不同子任务、不同模型、不同 prompt 模板下产生的 u，彼此的刻度并不相通，把它们放进同一个 Σ 里归一化，等于把摄氏度与华氏度相加。解决方式不是修公式，而是**分层分配**：先在层间按业务权重分，层内才用 u 分。分层之后，跨层的比较不再是「谁的 u 大」，而是「哪一层的边际产出高」——这恰好把问题拉回了本机制的第一性原理，只是换成了更高层级的一个版本。

### 规模带来的唯一好处：估计会变干净

规模并非只有坏消息。当同一类步骤被跑过上千次，历史错误率可以成为极高质量的 u（FAQ Q7 把它排在第一位），此时实验 3 里的 σ 显著下降，依赖输入的策略重新变得有价值。这是一条罕见的**正规模效应**：规模在这里修复的是输入，而不是修复机制。

### 前兆指标：三个要盯着看的量

① `sum(result)/B`（会计健康度）；② `实花/预算` 的分布方差（生成器守约度，合规率低于 80% 就该先修生成器）；③ **满足率**（实验 9 的那个比例）——它是唯一能把「该用哪个策略」变成日常可算数的指标。这三个量都不需要额外基础设施，几行日志就能算出来。

### 小规模的陷阱：n=2 时一切看起来都很美

当只有两个步骤，「比例 vs 均匀」的差别常常淹没在噪声里。这会让人误以为「分配不重要」，从而在系统长大时不设任何守卫。正确的态度是：**规模还小时就先把监控和边界写进去**，因为等到 n=40 时才发现 floor 失控，改造成本要高一个数量级。

> 一句话记住：本机制随规模坏的方式是**会计先崩、可比性后崩**，而修复成本随时间指数上升。所以守卫要早写，哪怕现在看起来是过度设计。



## 激励相容：谁有动机用它，谁有动机绕过它

机制不运行在真空里，它运行在有人的系统里。谁会因为「多给预算」受益，谁会想办法绕过它——这一章把这件事摊开讲。

### 受益者：预算充裕且曲线干净的团队

在实验 9 的 B≥4800 区间，比例分配有 1%–3% 的真实收益，且此时接口的可解释性（「难的多给」）在向上汇报时非常好用。注意这里出现了**双层收益**：技术上的 2%，与叙事上的「我们做了智能分配」。分清这两者，是本节最重要的提醒。识别的办法很简单：把这个机制关掉，看还有多少人愿意重新打开它——如果答案取决于汇报场合而不是指标，那么它的收益主要在叙事层，而不在技术层。

### 绕过者一：把 n 调大以抬高实际总额

如果某团队的配额是「总预算 B」，而实际支出被 floor 抬到 3.2 倍，那么**把任务切得更碎**就成了一个绕过预算上限的合法操作。这不是假设：它与「把项目拆成多个小项目以规避审批阈值」完全同构。治理方式：对 `Σb` 而非 `B` 计费，或把 n 纳入配额计算。

### 绕过者二：把 u 报高

既然 u 越大拿得越多，而 u 由各团队自己的模块产出，那么在跨团队的资源池里，**虚报不确定性**是理性行为。这与企业预算里各部门虚报需求的机制一模一样。治理方式：让 u 的产出者与 u 的受益者分离（由中性观测器出 u），或对历史虚报做校准衰减。

### 制度设计：三条把激励对齐的做法

① **事后清算**：按实花而非申报额计费，让「申报更多」失去动力；② **随机审计**：抽 5% 的步骤重跑一遍，让虚报 u 变成有代价的行为；③ **共享基线收益**：把策略退回「均匀」所省下的成本按比例返还给使用方，让「主动弃用更花哨的策略」也能得到回报——这是最难做但最关键的一条。

### 第三条绕法更隐蔽：让 u 的口径定义权归自己。谁定义了「什么算不确定」，谁就定义了资源流向，而这件事通常不会出现在任何设计文档里，也不会出现在任何复盘里。为什么会演化成这样

因为「多申请资源」在几乎所有组织里都是**无成本的尝试**，只有撞到硬约束时才会有负反馈。所以制度设计的第一性问题不是「怎么惩罚虚报」，而是「怎么让虚报当场就有价格」。这一条对所有涉及资源申请的机制（不限本仓）都成立。

> 记住：如果你的系统是跨团队协作的，**先设计激励，再设计公式**。公式错了可以改，激励错了会被人绕过，而且绕过的那批人从不写复盘。判断一套制度是否健康的速测：问三个使用方「如果今年少报 20% 会怎样」，如果没人答得上来，说明价格信号还没有建立。



## 权力与伦理：它让谁更强、让谁更弱

所有资源分配机制都自带权力属性：它决定了谁能获得什么。预算分配听起来离伦理很远，直到你意识到它决定了「哪些问题值得被认真思考」。

### 受益方：能被量化为 τ 的任务

本机制默认把 τ 可测量的步骤当作一等公民。代价是：**那些难以量化收益的步骤——例如「这一步是否该更谨慎」「这是否涉及敏感人群」——因为给不出 u，就在分配里被系统性边缘化。**它们拿不到预算，不是因为不重要，而是因为不可测量。而可测量性与重要性之间的相关性，通常远低于我们的直觉。

### 受损方：最难、同时也最边缘的环节

实验 8 里最难的那一步拿到 0 预算，这在数学上对，在工程上有风险：如果那一步恰好是安全审查、事实核查、或弱势群体的例外处理，那么「在预算约束下把它砍掉」就不是效率，而是**把风险转嫁给没有发言权的人**。这是本机制必须配人工复核的第一个理由。

### 红线：三类不可进入竞价的步骤

① **安全与合规检查**：它们不参与按收益排序的优化，必须获得全额保障；② **事实核查与引用**：它们的收益长期滞后，短期曲线看不见；③ **涉及人身重大影响的输出**（医疗、法律、信贷建议）：这些领域的压缩后果不由开发方承担。把它们列为「不可压缩清单」，比任何参数调优都重要。技术上这只是几行配置：把这几类步骤从 u 排序里剔除，写死全额。难的部分在别处——承认「按效率排序」的清单一旦开始扩张，第一个被挤掉的几乎总是治理与合规。

### 可审计性作为最低要求

如果一笔资源被从某一步挪走，必须留下可追溯的记录：谁决定、依据什么、何时生效。实践节第 4 项要求记录 `(step_id, u, budget, 实花, 产出)`，它既是调试资料，也是**问责的基础**。一个不记录分配决策的系统，本质上在做不可申诉的决策。

### 一个不太舒服的观察

「效率优先」的资源机制几乎总是先把成本转嫁给最缺乏议价能力的一方，因为那一方的反馈最慢、最难被听见。唯一的对冲是**在机制之外保留一条不参与优化的保底通道**：把它写下来自有用处——当有人试图绕过它时，团队至少有一句已经被记录的话可以引用。它低效、表面上是浪费，但它是这套东西不至于演变成压迫的那根保险丝。

> 本机制的中性只在技术层面成立；一旦接进真实系统，「不给」就是一个决定，而任何决定都需要有能被质询的依据。写进 README 的意义不在道德姿态，而在于当有人问「这一步凭什么被砍掉」时，答案必须是设计出来的，而不是预算表算出来的。



## 十年尺度：它会被什么取代

最后一个角度：把时间拉到十年。这一章的价值不在于预测准，而在于**提前识别哪些部分现在就该做成可替换的**。

### 最可能取代它的东西：模型内部的自我预算

最合理的演化路径是：未来的推理模型自己在推理过程中决定「这道题要多少步、每步多长」，外部静态分配器则退化为一层测试用的 stub。这不需要突破性技术，只需要「自适应算力」成为模型的原生能力。时间尺度我给 2–5 年（这是判断，不是预测，没有外部数据源）。判断这条路是否已经到来的信号很简单：如果你开始无法向用户解释「为什么这一次想了这么久」，说明预算的决定权已经移到了模型内部。

### 第二个变量：单位 token 的价格继续下跌

如果思考 token 的价格再降两个数量级，「分配」这件事会像 1990 年代的「手工优化内存」一样退出讨论。届时真正稀缺的会变成**注意力与核验能力**，而不是思考预算。本仓会让位给 P01（早停）与 P12（失败考古）那一类机制。

### 第三个变量：被更传统的运筹学收编

LLM 工程有一个反复出现的模式：先把某个运筹学问题重新发明一遍，几年后才发现教科书里几十年前就解过了。预算分配正是其中之一：背包、注水（water-filling）、随机调度三个经典结构已经覆盖了本仓讨论的全部情形。推演：本类机制最终会被写成「带 LLM 特色的资源调度」章节，而不是一个独立话题。

### 不变的部分：三条不会被取代的判断

① **看边际收益，而不是看标签难度**，这条是数学而非技术；② **输入质量决定策略价值的上限**（实验 3，σ=2.0 时最优塌 21.9%），这条在所有数据驱动领域通用；③ **「什么都不优化」必须被列为第一选项**——这条属于工程文化，与技术无关。即使本仓代码明天就被删掉，这三条仍然成立。把它们写成判据而不是结论是有原因的：判据可以在不知道未来技术形态的情况下被使用，一个用技术名词写成的结论会在技术换代那天死去，一个用取舍关系写成的判据不会。

### 给十年后的读者留的话

如果你是在 2036 年读到这一段，而本仓看起来像在用打字机讨论云计算，请先别急着删：**去 `bench_p02.py` 里把收益曲线换成你那个时代的真实曲线，重跑实验 9。**如果结论翻转了，请提 issue 并把对比贴在 issue 里——那将是这份文档最有价值的一次更新。

> 机制会过期，写下的判据与可复现的实验不会。这就是把 README 写成 2 万字而不是 2 百字的理由：**少的部分会过时，多的部分留得住。**



## 边界：该用 / 不该用 / 失效模式

### 适用条件（全部满足才用）

1. 一次回答已被切成 n≥2 个可独立限额的步骤，并且你能给每步设 `max_tokens` 或等价上限
1. 每步都有一个**外部观测到**的不确定性数值（草稿分歧、检索置信、历史错误率），不是模型自评
1. 总预算相对固定：你知道这一串步骤一共能用多少思考 token
1. 生成器会遵守限额：给了 150 就会在 150 附近停（否则你就只是在建议，不是在分配）
1. 你能记录每步实花与产出，用于事后判断在这里到底该选比例还是均匀

### 禁用条件（任一命中就停）

1. 步骤之间存在强依赖：后面的步骤需要前面的产出才存在，静态一次性分配会把预算押在不存在的步骤上
1. 不确定性是常量（所有步取值相同）：此时比例分配等于均匀，却多引入一个「看起来在做智能决策」的故障面
1. 单步却硬切成多步凑分配：没有任何信息增量的切分只会带来 floor 抬升与账目失真
1. 你的真实瓶颈是「整体 token 太多」而不是「比例不对」：先做压缩（P04）或早停，别先做分配
1. 计费/限流是按整次调用而非分步结算，且没有分步预算开关：分配出去的数字不会被真正执行

### 失效模式

| 失效模式 | 症状 | 处置 |
|---|---|---|
| 保底失控 | 步数增多后总支出远超预算，实测 n=32 为 1.60 倍、n=64 为 3.20 倍，长尾分布 3.55 倍 | 在返回后立刻断言 `sum(result) <= budget * 1.1`，超出就改用相对保底并重算；把倍数写进监控 |
| 负不确定性 | `allocate([-1.0, 2.0], 1000, 50)` 返回 `[50, 2000]`，总额翻倍且无告警 | 调用侧加 `assert all(u >= 0 for u in uncertainties)`，并单独处理全零情形 |
| 全零信号 | `allocate([0,0,0,0], 1000, 50)` → `[50, 50, 50, 50]`，在没有信息时默认花掉 200 token | 检测到 Σu≈0 时直接降级为均匀分布并打点，不要假装这是「一次有依据的个性化结论」 |
| 生成器不守约 | 分配形同虚设：给了 150 的模型写了 400，另一处给了 300 只写了 20 | 先验证「实花 ≤ 预算 ×1.1」的合规率，低于 80% 就别引入分配器，先修生成器的停止条件 |
| 比例输给均匀而无人察觉 | 在预算中等的场景收益低约 13%，但系统无任何异常信号 | 把 `gain_per_strategy` 做成离线对照期：每周跑一次均分对照组，差距 <2% 时改用简单的那个 |
| 步数漂移 | 步骤数从 6 涨到 40，floor 抬升把单一 path 的成本结构改写，历史基线全部失效 | 对 n 设上限（建议 ≤16），超过就合并相邻步骤而不是继续增加 n |



## 常见误用与反例

### 反例 1 · 把本仓当优化器

**错法**：以为接上 `allocate` 就会「省钱又提质」，把原来的均匀分配替掉，不看对照

**后果**：在饱和型收益、预算中等的场景，实测这是**净损失**：4.006 对比均分 4.621，落后 13.3%。一个没有对照组的替换不是优化，是赌博

**正法**：先在影子模式下跑一周：两种策略各记 $(实花, 产出)$，用同一批样本比较再决定是否切换

### 反例 2 · 用模型自评当不确定性

**错法**：`uncertainties = [float(model.confidence(x)) for x in steps]`

**后果**：自评置信度系统性偏高，且恰在最需要多想的地方最自信；输入脏了，公式再正确也没用。实测在估计噪声 σ=2.0 时，比例分配收益下降 8.1%

**正法**：改用行为观测量：同一步生成 K 份草稿算分歧（P01）、检索返回的重合度、历史同类题的错率

### 反例 3 · 在流程刚跑完第一步时就静态锁死预算

**错法**：把预算一次性分完后不再调整，即使第一步只花了预算的 10%

**后果**：静态分配把「省下来的」留在了没人用的地方，而后面的步骤还在挨饿

**正法**：采用两段式：先发 60%，剩余每完成一步按实花重算（":" 见生产化清单第 3 项）

### 反例 4 · 用 floor 兜住不确定性估计的质量问题

**错法**：估计常年偏斜，于是把 floor 调大到 200 让「至少不会漏」

**后果**：实测 floor 从 50 调到 200，极差比从 7.5× 压到 1.9×——你等于亲手把分配改成了均匀，同时还保留着 1837/1200 的超支。想要均匀就直接写均匀，别用它来伪装

**正法**：想要保底就调小不确定性分布的方差，想保分配就先用相对保底；不要把 floor 当旋钮乱拧

### 反例 5 · 按cot-Th步数而非难度

**错法**：步骤越多每步拿到的越少是「合理的」，于是不限制 n

**后果**：n 增大到 32/64 后预算被 floor 吃掉 60%-220%，且步数本身是从 prompt 里抽出来的噪声

**正法**：把 n 当作需要治理的产品决策：设上限，合并语义相邻的步骤

### 反例 6 · 拿比例分配的结果充当可解释性

**错法**：向用户解释「因为这一步不确定性高达 0.8，所以给它 375 token」

**后果**：这个解释里的每个数字都来自一个从未被验证为正确的假设（收益与投入成正比），把它讲给用户等于把未经验证的模型伪装成理由

**正法**：解释要么换成「这一步历史上错得多，所以多给」，要么干脆不解释



## 与替代方案对比

诚实地说：本机制不是唯一解。下表列出常见替代，以及什么情况下该选它们而不是本仓。

| 替代方案 | 与本仓的核心差异 | 何时应选它 |
|---|---|---|
| 均匀分配 B/n | 完全忽略难度，每步一样多 | 当你的预算充裕度落在中等区间时——实测 B=1200、n=8、τ∈[40,600] 时它收益 4.621，胜出 13.3%。它也应该是你的默认基线，而不是比例分配 |
| 早停 / 自一致性过滤 | 不分配，而是先跑 K 份，答得一致就提前结束 | 当步之间存在强依赖、无法静态切分时；P01 属于这一类，它与本仓互补而非竞争 |
| 按边际收益注水（water-filling） | 解拉格朗日：令各活跃步的边际收益相等再分配总量 | 当你的收益曲线可估计且噪声小；实测收益 4.740 对比例 4.006 领先 18.3%，但它的分配形状反直觉——最难的一步拿到 **0** |
| 阈值触发式加预算 | 每步先给一个小额，检测到「还没会」的信号才追加 | 当不存在跨域统一的不确定性刻度时；它把「估计」换成「判决」，通常更稳 |
| 模型降档（P03） | 不给难步更多思考，而是把难步换给更强的模型 | 当思考 token 的边际收益明显低于换模型的边际收益时；两者经常是替代关系而非叠加 |
| 压缩后统一额度（P04） | 先把思考压短，再在所有步之间平均 | 当上下文长度才是主要成本项时；压缩改变的是「总量」，本仓改变的是「结构」，两者不解决同一个问题，别指望择一即可 |
| 按历史错误率加权 | 不用即时不确定性，用同一类步骤过去的错误记录 | 当即时估计太贵或太脏时；它牺牲响应速度换取统计稳定性 |

## 可复现实验与验证协议

一个机制「有用」不是靠断言，是靠能被证伪。下面每个实验都给出**操作步骤 + 判定标准**，任何人可独立复跑。

### 实验 1 · 实验 1 · floor 抬升破坏总量守恒

跑 `python deep/bench_p02.py` 的第一节。构造 n ∈ {2,4,8,16,32,64} 的两种分布：均匀不确定性 `[1.0]*n` 与长尾 `[1/(i+1)**1.2]`，固定 B=1000、floor=50，计算 `sum(allocate(...)) / B`。

**判据**：判据：n≤8 时比值应在 1.00–1.02（实测 1.00/1.00/1.00/1.02）；n=16 长尾时 **1.29**；n=32 时均匀 1.60、长尾 2.01；n=64 时 **3.20 / 3.55**。若你的数字符量级一致，说明 floor 的破约行为在所有机器上都可复现；若比值为 1.00 直到 n=64，说明你改了 floor 语义，本结论对你不适用。

### 实验 2 · 实验 2 · 四种分配策略的直接对比

n=8，τ=[40,70,110,160,220,300,420,600]，B=1200，收益用饱和型 `w(1-e^{-b/τ})`，四种策略：均分、按比例、赢家通吃、拉格朗日最优。

**判据**：判据：实测 均分 **4.621** > 按比例 **4.006** > 赢家通吃 **0.865**；最优 **4.740**。三条都可独立验证：① 比例分配不是中预算下的最优；② 它甚至输给了不动脑的均分；③ 赢家通吃在任何形态下都是最差策略。若你的结果里比例 > 均分，请检查 τ 跨度是否足够大。

### 实验 3 · 实验 3 · 估计噪声对「更聪明」的策略伤害更大

对真实不确定性加对数正态噪声 N(0,σ)，σ ∈ {0, 0.25, 0.5, 1.0, 2.0}，每种跑 200 次取平均。关键：连理论最优策略也只能看到被噪声污染的输入。

**判据**：判据：σ=0 时 均分 4.621 / 比例 4.006 / 最优 4.740；σ=2.0 时 均分 4.621（不变）/ 比例 **3.681** / 最优 **3.701**。两条结论：① 依赖输入的策略随噪声单调劣化；② **在 σ=2.0 时最优解几乎不再优于按比例**，也就是脏输入环境下为「最优」付出的复杂度全部白费。这条能直接指导你先修什么。

### 实验 4 · 实验 4 · 长尾难度：7 步简单 + 1 步极难

τ=[30]*7 + [900]，B=1200，比较四种策略，特别看「极难那一步拿到多少」。

**判据**：判据：均分 7.106 > 按比例 6.338 > 赢家通吃 0.736；最优 **7.204** 给最难步 394（不是 1200）。这是本仓最反直觉的一处：**最优解给最难的一步的预算，只有赢家通吃的三分之一**。若你以为「难就该多给」，这个实验会同时证伪你和赢家通吃。

### 实验 5 · 实验 5 · 分配函数自身的开销

n ∈ {8, 64, 512}，随机不确定性，每种 20,000 次调用求平均单次耗时。

**判据**：判据：实测 1.18 / 7.29 / 56.28 µs，严格线性。结论：任何试图优化这段函数的努力都是浪费——它在一个 100 ms 级调用里占 1e-5。如果你在性能剖析里看到它上榜，说明你的瓶颈在别处，或者你的 n 已经大到该拆步骤了。

### 实验 6 · 实验 6 · 防御性输入检查

直接调用三种病态输入并肉眼核对返回值。

**判据**：判据：`allocate([0,0,0,0],1000,50)` → `[50,50,50,50]`（无信号仍花 200）；`allocate([-1.0,2.0],1000,50)` → `[50,2000]`（总额 2050，**两**倍，无告警）；`allocate([],1000,50)` → `[]`（静默通过）。这三条同时构成「必须在上层加校验」的证据链：它们不是边界理论，是必然会被触发的现实输入。

### 实验 7 · 实验 7 · 收益曲线的形状决定胜者

固定同一份 τ，只替换收益函数：饱和型 `1-e^{-b/τ}`、线性型 `min(1,b/τ)`、阈值型 `min(1,(b/τ)²)`，各跑四种策略（最优用随机方向爬山，非凹目标不能用拉格朗日）。

**判据**：判据：三种形态下「数值最优」都以明显优势胜出（4.740 / 6.682 / 6.476），而比例分配在三者中分别为 4.006 / 5.452 / 3.839，均劣于同场景的均匀 4.621 / 5.726 / 4.784。**这是本仓最重要的一条：决定「该不该按难度分配」的不是难度，是收益曲线的形状。**任何脱离曲线谈比例的讨论都没有信息量。

### 实验 8 · 实验 8 · 最优分配的形状：它会放弃最难的一步

对实验 2 的场景解拉格朗日，打印最优向量，并与比例向量并列。

**判据**：判据：最优 `[107, 149, 184, 207, 215, 200, 139, 0]`，比例 `[50, 50, 68, 100, 137, 187, 262, 375]`。两者几乎是**镜像**：最难的一步在最优解里拿到 0，在比例解里拿到最多。这条可以直接用：当你的系统里存在「怎么投都投不会」的步骤时，正确动作是把它的预算挪走并交给人类或更强的模型，而不是继续加码。

### 实验 9 · 实验 9 · 预算充裕度决定胜负：存在交叉点

固定 n=8 与 τ，扫描 B ∈ {400, 800, 1200, 2400, 4800, 9600, 20000}，每个 B 比较均分与比例，并统计最优解下达到收益 0.9 的步数占比（满足率）。

**判据**：判据（实测比例/均分之比）：B=400 → **1.090（比例胜）**；B=800 → 0.876；B=1200 → **0.867（比例最劣）**；B=2400 → 0.943；B=4800 → **1.025（比例重新胜）**；B=9600 → 1.021；B=20000 → 1.002。满足率分别是 0% / 12% / 12% / 38% / 75% / 100% / 100%。**结构性结论：预算极度稀缺时比例胜；中等时均匀胜；充裕时两者趋同，比例微弱领先。**这条给了本仓唯一可靠的启用判据：先算你的满足率，再决定用不用比例分配。

### 实验 10 · 实验 10 · floor 的真实作用是压缩极差，代价是超支

固定 u 与 B=1200，扫描 floor ∈ {0, 25, 50, 100, 200}，记录总额、最小步、最大步、极差比。

**判据**：判据：floor=0 与 25 时极差比均为 15.0×、总额 1197；floor=50 极差 7.5×、总额 1229；floor=100 极差 3.8×、总额 1361；floor=200 极差 1.9×、总额 **1837（超支 53%）**。结论：floor 本质是一个「反分配」旋钮，拧到 200 你已经得到了均匀分配，却仍在为「动态算出来的分配逻辑」付出维护成本。

## FAQ

### Q：Q：为什么说「难的步骤不该多给」？这不是常识吗？

常识是「难的多给」，正确性是「边际收益高的多给」，两者只在收益与投入成正比时才重合。饱和型收益下第 i 步的边际收益是 (1/τ_i)·e^{-b_i/τ_i}：τ 越大，起点的边际收益越低。实测 τ=600 的那一步在最优解里拿到 **0**（实验 8），而比例分配给了它最多的 375。常识错在把「难」当成了「值得投」，跳过了一个必要的中间变量。

### Q：Q：那本仓还有什么用？直接删掉不就行了？

三件事：① 它把「分配」这个问题从争论变成可执行的接口，你可以换实现不换调用；② 它自带十个可复跑的实验，能直接告诉你**在你的分布上**该不该用比例；③ 它在预算极度稀缺时确实领先 9.0%（实验 9，B=400）。一个把自身适用边界量化出来的机制，比一个宣称万能的机制有用得多。

### Q：Q：README 里的收益数字是真的 LLM 跑出来的吗？

不是。它们是**合成收益曲线**上的数值（`1-e^{-b/τ}`、`min(1,b/τ)`、`min(1,(b/τ)²)`），用来比较策略的相对优劣，不能用来预测真实收益。换机器重跑 `deep/bench_p02.py` 应得到一致数量级。为什么敢这么用：因为结论依赖的是曲线的**形状**（凹 / 线性 / 阈值），不是它的具体参数。真要上线，用你自己的历史数据拟合一次 τ 与形状，再跑实验 9。

### Q：Q：我该先看哪个数字来决定用不用它？

预算充裕度，即 B / Στ。跑实验 9 的扫描，看你的系统落在哪一段：满足率 0%（极度稀缺）用比例；满足率 12%–38%（中等）**用均匀**；满足率 75% 以上两者相差不足 3%，用哪个都行，优先用简单的那个。

### Q：Q：为什么全零不确定性会返回每步 50 而不是报错？

因为参考实现把 `s = sum(u) or 1.0` 当成防御，而不是当成语义。全零的真实含义是「没有任何信息」，正确动作应该是降级为均匀分布或向上游报错，而不是花 200 token 买一个伪装的均匀下注。生产化清单第 2 项要求你在调用侧补上这个校验。

### Q：Q：floor 到底该设多少？

按 n 反推：`floor ≤ B/(2n)` 时总额超支可控制在 ~25% 内。n=8、B=1200 时 floor ≤ 75（实测 floor=100 总额 1361，超支 13.6%；floor=200 超支 53%）。更好的做法是改成相对保底 `B/(2n)`，它会随步数自动收缩，代价是失去了「最小思考单位」的物理解释。

### Q：Q：不确定性到底该从哪来？

三个来源按可靠性排序：① 历史错误率（最稳，但要足够的量）；② 同一批样本的草稿分歧度（P01 的一致性反过来用）；③ 检索 or 规则的外部信号。**不要**用模型自评置信度：它在最该多想的地方最自信，等于在最需要的地方关掉预算。

### Q：Q：噪声多大的时候就没必要用聪明策略了？

看实验 3：σ=2.0 时理论最优 3.701 已经几乎不再优于按比例 3.681（差距 0.5%），而两者都在 σ=0 时落后于均分。换句话说：**当你的不确定性估计脏到一定程度，追最优性没有回报，不如花时间把估计做干净，或者干脆用不依赖输入的均匀。**

### Q：Q：赢家通吃为什么输得那么惨（0.865 vs 最优 4.740）？

因为它把所有预算压到一个边际收益早已衰减的位置，同时让其余 7 步拿 0，而它们的 τ 小、只要几十个 token 就能接近满分。这个对比的价值在于说明：**在存在多个「便宜的满分」的世界里，把资源集中到唯一一个「昂贵的及格」几乎总是错的。**

### Q：Q：和 P01（草稿一致性路由）怎么配合？

P01 决定「这一步要不要深度思考」，本仓决定「在要思考的那些步之间怎么分」。两者是串联的两级：P01 砍掉不该想的，本仓给剩下的定价。顺序不能反——先算总额（P01 决定了 n 和 B），再分配（本仓）。

### Q：Q：和 P03（置信度门控换模型）怎么选？

两者都是给难的部分更多资源，只是一个给 token、一个给更强的模型。判据：如果某一步 τ 巨大且 isolated（例如一个独立子问题），换模型通常更划算；如果难度是多步共同造成的，加思考 token 更划算。实测角度不在这两仓的范围内，需要你用自己的数据做一次对照。

### Q：Q：为什么验证了那么多，还是担心白忙？

因为单个机制的最佳实践永远是场景相关的，而本 README 只能给判据、不能给答案。真正防白忙的是实验 9 那个扫描：它把「用不用」变成一个**每天可以重算的数**。把它做成 CI 里的深夜任务，比读十篇最佳实践有用。

### Q：Q：我发现本仓结论和我的实测相反，怎么办？

先检查三件事：① 你的 τ 跨度是否 ≥ 一个数量级（本实验是 40→600，15 倍）；② 你的收益曲线是否属于饱和型（多数 token 密集型任务的答案是「是」）；③ 你的满足率落在实验 9 的哪一段。如果三者都检查过仍相反，那是本仓最有价值的时刻——请提 issue 附上你的三个参数，这条反例会直接进入下个版本的「已知边界」。

### Q：Q：为什么 floor 抬升之后不做二次归一化？

做了就违反保底语义（保底会被压缩回去），不做就违反会计约束（总额超支）。这是**两个正当要求之间的真实冲突**，不是没想到的疏漏。本仓选了「保底优先」，因为 correctness 层面的「每一步至少有一次机会」比 accounting 层面的「恰好等于预算」更重要；后者可以在上层补回来。

### Q：Q：这个机制十年后还在吗？

「在若干个步骤之间分配预算」这个动作会一直在，但**由谁分配**大概率会变：一旦生成器的内部 transformer 能给自己的 COT 分配长度，外部静态分配器就退化为一个 test stub。不变的只有那条判据——「下一个 token 给谁最值」，以及它在绝大多数情况下的答案：**给收益能吃下去的那一步**。



## 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 思考预算 | thought budget | 某一步允许消耗的最大推理 token 数，是上限而非目标 |
| 不确定性 | uncertainty | 本仓唯一输入，须来自外部观测，禁止使用模型自评置信度 |
| 保底 | floor | 每步的最小预算；它会破坏总额守恒，是两者取舍的产物 |
| 边际收益 | marginal return | 多给一个 token 换来的额外收益，分配问题的唯一正确视角 |
| 饱和 | saturation | 投入不再带来产出增长的区间；它决定了「多给」是否等于「多得」 |
| 难度尺度 τ | difficulty scale | 达到约 63% 收益所需 token 数，把「难」翻译成可比较的单位 |
| 充裕度 | budget adequacy | B/Στ，决定「比例」与「均匀」谁赢的那个量，见实验 9 |
| 满足率 | satisfaction rate | 最优分配下达到收益 0.9 以上的步数占比，充裕度的可观测量 |
| 注水式分配 | water-filling | 令各活跃步边际收益相等的拉格朗日解；它会给最难的一步 0 |
| 收益曲线形状 | return shape | 投入→产出函数的形态；它而非难度，才是「怎么分」的决定量 |
| 静态分配 | static allocation | 一次性算完不再调整；无法回收提前停止省下的预算 |
| 相对保底 | relative floor | floor = B/(2n)，随步数收缩，规避长流程超支 |
| 估计噪声 σ | estimation noise | 不确定性观测的对数正态噪声；σ=2.0 时最优策略不再优于比例 |
| 赢家通吃 | winner-take-all | 全部预算给最难一步；实测在三种收益形态下均为最差策略 |

### 家族内相邻机制

- P01 `no-think-draft-agreement-router` — 决定「这一步要不要深度思考」；本仓决定「在要思考的那些步之间怎么分」。两者串联才构成完整的两级成本控制。
- P03 `confidence-gated-reasoning-switcher` — 给难的步骤换更强的模型；与本仓是同一目的的两种资源形式。**选择判据**：差异来自该步是否可隔离。可隔离 → 换模型（P03）；不可隔离 → 加思考预算（本仓）。
- P04 `cot-compression-router` — 压缩思考总量，而非重分配结构。**两者不解决同一个问题**：先问总量（P04），再问结构（本仓）。
- C01 簇 `eim-c01-adaptive-thinking-routing` — 本仓所属的四个成员与分工，簇仓的综述给出同簇内部的选择树。

- 家族旗舰仓 `emergent-mechanisms` — 55 个机制全景、统一评测协议与家族术语总表；本 README 的实验方法遵循其中的负对照要求。

## 关于 EIM-1.0 家族

**EIM**（Emergent-Intelligence Mechanisms）把 AI 系统里「自己长出来」的能力——少想、
省 token、互相压缩语言、卡住了知道自己卡住、自己修自己——一个个拆出来，做成零依赖、
可运行、可自检的参考实现。当前收录 55 个机制，分 14 簇。

**家族的四条共同约定**：

1. **零第三方依赖**。只允许 Python 标准库。装不上就跑不起来的实现，不算参考实现。
2. **默认可证伪**。每个仓都有 `selftest.py`，含正对照与负对照；没有负对照的自检等于没自检。
3. **输出可快照**。`golden_output.txt` 记录发布时的真实输出，行为漂移会被自检抓住。
4. **双向同步**。本仓实现与组合仓 `emergent-mechanisms` 中对应组件保持一致，修复同改两边。

**本仓定位**：`P02` 属于 **自适应思考路由** 簇。它是该机制的单点署名锚——可单独引用、
单独开 issue、单独打星；簇级综述请见该簇仓，全景请见组合仓。

看「代码逐行导读」与「设计决策」；要评估可信度，看「可复现实验」。
