# P04 · 01-problem-and-model

> 属于 [P04 cot-compression-router](../README.md) 的文档分册。


## 问题：它到底在解决什么

### 真实场景

一条完整的推理链往往是啰嗦的：模型会重述题意、试探性地列一个式子、自我否定一次、再重新来过。真正推动结论的通常只有那么几步。把这条链原封不动地交给下一步——无论是交给同一个模型的下一轮，还是交给另一个 Agent，或者塞回上下文——都要为那些废话付 token 钱。最自然的省法是「把关键的留下，其余丢掉」。本仓做的事就是这句直觉的七行实现：保留第一步、最后一步，加上**最长的** k-2 步。「最长」在这里扮演了一个角色：**信息密度的代理指标**。这个代理好不好用，就是本 README 用两万字要回答的唯一问题。

### 朴素做法为何失败

朴素做法有两层。第一层是「保留最后 k 步」，理由是新近的信息更重要；第二层是「保留最长的 k 步」，理由是写得多的地方想得深。本仓实现的是第三层：两者结合的产物——**保底给首尾两个位置，剩下的名额给最长的那些**。这个设计在纸面上很合理：第一步通常框定了问题，最后一步通常给出结论，中间的预算则按「信息密度」分配。问题出在那个「信息密度」是用**长度**来代理的。而我们的实测给出了一个很难看的结果：把「长度」与「重要性」的真实重合度作为参数 rho，当 rho=0（两者完全无关）时，本仓的保真度是 **0.437**，而**随机抽样 k 步的保真度是 0.508**——随机赢了 0.071。更糟的是代价：本仓此时保留的 token 比例是 0.609，随机是 0.507。**本仓花更多的钱，得到了更差的结果。**这不是随机波动。因为随机抽样是**无偏**的，而本仓是**有偏**的——当那个偏差指向错误的方向时，「有系统」比「没系统」更糟。这条结论是全篇最重要的东西，它把「有没有做优化」和「优化有没有用」彻底分开了。

### 失败的代价

代价可以分成看得见和看不见两类。**看得见的那部分反而较轻**：丢失的保真度会体现在下游答案变差上，虽然难以归因，但至少能被聚合指标捕捉。**看不见的部分有四项，每一项都比损失本身更难处理。**其一，**接口不保留身份**。`compress()` 返回的是一个文本列表，丢弃了「这是第几步」这件事。当两条步骤文本相同时（真实 CoT 里「好的」「让我检查一下」这类重复极多），调用方用 `list.index()` 回查会全部命中同一个位置（实验 11 实测 `[0, 1, 4]`）。这意味着依赖修复、链路重建、审计追溯这三件事在结构上都无法实现。其二，**非幂等**。`compress(compress(x)) != compress(x)`，实测 12 步 → 5 步 → 2 步 → 2 步。每一次调用都是合法调用，没有任何异常或告警。在一个有多级 summarization 的流水线里，这个性质会在你不知道的地方触发第二次压缩。其三，**契约两端都对不上**：`keep_ratio=0.0` 仍返回 2 步，`keep_ratio=1.0` 在 n=12 时平均只返回 10.38 步（丢了 13.5%）。其四，**悬空引用**。约 14%–18% 的保留步骤会引用一个已被删除的步骤，而带依赖闭包的 oracle 可以把这个数做到 **0**。这些不是性能损失，是正确性损失。最后一层代价是认知上的：`keep_ratio` 这个参数名让人以为它是一个线性的旋钮——调到 1.0 就该不压缩。实测它既够不着 1.0 也够不着 0.0，而因为文档没写，调用方会默认自己拿到了自己要的东西。



## 概念模型与术语

**步骤（step）** — 思维链的一个切片。本仓不定义边界——怎么切是调用方的事，而这一步其实决定了后面所有数字的含义。按句号切、按段落切、按工具调用切，会得到完全不同的「步骤」。本仓所有实验默认 12 步。

**信息密度代理（proxy for importance）** — 本仓用**字符长度**作为「这一步有多重要」的代理。这是整套机制的命脉，也是它最脆弱的地方。**代理不等于被代理的量**——这一点在实验 1 里被量化到了小数后三位。

**重合度 rho** — 本仓基准脚本里的显式参数，定义为「最长的那批」与「最重要的那批」之间的真实重合比例。rho=1.0 表示长度完全可靠（对本机制最有利）；rho=0.0 表示两者无关（对本机制最不利）。**这个参数是本仓诚实性的核心**：它把「长是不是重要」这个未经证实的信念变成一个可以被讨论、被测量、被反驳的数。

**保真度（fidelity）** — 保留步骤的重要性之和 ÷ 全部步骤的重要性之和。注意这是相对我们赋予的地面真值而言，不含任何真实 LLM 评估。

**悬空引用（dangling reference）** — 保留了一步，但它所依赖的某一步被删除了。这是压缩器的**特有**失效模式：它不像「删错了关键步」那样会被聚合指标捕捉，它产生的是一个看起来完整、实则缺少前提的推理片段。

**幂等性（idempotency）** — `f(f(x)) == f(x)`。本仓**不满足**这条。对大多数「处理」类函数而言幂等是默认期望，本仓是反例——而把反例写清楚，比假装它满足更有价值。

**零信息基线（zero-information baseline）** — 不做任何挑选、随机保留 k 步的结果。**任何挑选策略都必须先打败它**，否则它只是在给系统增加偏差。本仓在 rho≤0.2 时打不过这条基线。

**依赖闭包（dependency closure）** — 挑选某一步时把它引用的步骤一并补齐。这是消除悬空引用的标准做法，本仓没有实现它，而《生产化改造清单》把它列为 P0 级别的第一项。

### 概念之间的关系

```text
原始思维链 --切成--> 步骤序列 --按长度排序--> 候选名次
保底名额 {首步, 末步} + 选优名额 top(k-2) by length --set 去重--> 保留索引
保留索引 --取文本--> 返回列表（**身份信息在此丢失**）

★ 三条关键因果：
  ① rho 越低 -> 长度偏差越指向错误方向 -> 越可能输给随机抽样（rho=0 时输 0.071）
  ② 删除任何一步都可能切断依赖边 -> 悬空率 14%~18% -> 下游产生无前提的推理
  ③ 返回值是文本而非索引 -> 重复文本不可区分 -> 无法回溯、无法修复、无法审计
```
